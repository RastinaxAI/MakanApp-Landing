# یکدست‌سازی کامل پنل مدیریت

مرجع مورد تأیید مالک، صفحهٔ `/admin/content` است. در پاسخ صریح مالک، دامنهٔ کار «فقط تمام صفحات پنل مدیریت» تعیین شد. طراحی صفحات عمومی و محتوای منتشرشده در این تغییر دست‌نخورده‌اند.

## الگوی مشترک

عنوان ساده با توضیح کوتاه و مسیر صفحه، دکمهٔ اصلی مشخص، فاصله‌های منظم، سطح سفید با حاشیهٔ ظریف، فهرست پیوسته، برچسب وضعیت کوچک، شمار واقعی موارد کنار عنوان و تب‌های سبک، مبنای صفحات هستند. رنگ برند و فونت فارسی موجود حفظ شده‌اند.

صفحهٔ مرجع و قواعد اختصاصی آن حفظ شده‌اند. سایر صفحه‌ها اجزای مشترک `AdminPageHeader` و `AdminPanel` و سبک محدود به محیط مدیریت را استفاده می‌کنند. تفاوت وظیفهٔ صفحه‌ها در چیدمان لحاظ شده است: جدول CRM، فرم تنظیمات، فهرست رسانه و ابزارهای صفحه‌ساز هرکدام ساختار کاربردی خود را دارند.

| بخش | پوشش |
| --- | --- |
| ورود و وضعیت خطا | نوار برند، فرم ورود با همان OTP و MFA، پیام خطا و تلاش دوباره |
| داشبورد | عنوان مشترک، شمارهای واقعی و دسترسی‌های سریع متناسب با نقش |
| محتوا | صفحهٔ مرجع، مشخصات و ویرایش متنی، پرسش‌ها، تاریخچهٔ نسخه‌ها و نوار پیش‌نمایش |
| استودیوی طراحی | عنوان و کتابخانهٔ هماهنگ، راهنمای کوتاه، تب‌های یکپارچه، تنظیمات هویت و ساخت طرح |
| بوم صفحه‌ساز | هماهنگی رنگ و ابزارهای محیط ویرایش؛ طراحی سند داخل iframe و سازوکار کشیدن و رهاکردن حفظ شده‌اند |
| مرکز آموزش | فهرست، دسته و برچسب، ایجاد و ویرایش مقاله، ویدیو، مجموعه و وبلاگ و پیش‌نمایش |
| رسانه‌ها و پرسش‌ها | فهرست، جست‌وجو، بارگذاری و انتخاب تصویر، مدیریت دسته و تأیید حذف |
| CRM | گزارش فروش، لید، مدرسه، کانبان، فعالیت، دمو، اعلان، اتوماسیون، فیلتر و پنجرهٔ ثبت و ویرایش |
| پرونده‌ها | پروندهٔ مدرسه و لید، اطلاعات درخواست، پیگیری، یادداشت و تاریخچه |
| گزارش سایت | بازدید و نتیجهٔ فرم، رویدادها و نمونه‌های واقعی سرعت؛ توضیح روش محاسبه قابل بازکردن است |
| حساب و تنظیمات | مدیران، تنظیمات عمومی و SEO، پیامک، رویدادها، امنیت، نشست و MFA |
| دسترسی غیرمجاز | حفظ بررسی سمت سرور و نمایش پیام هماهنگ با پنل |

پیش‌نمایش محتوا، طراحی واقعی سند را نمایش می‌دهد و ابزارهای خصوصی مدیریت در نوار جدا مشخص هستند. رنگ و تنظیمات طراحی محتوا به‌دلیل هماهنگ‌کردن پنل تغییر نمی‌کنند.

## حفظ رفتار و داده

API، مدل، Migration، نقش‌ها و سازوکار احراز هویت جدیدی اضافه نشده است. فرم‌ها به همان APIها متصل‌اند. محتوای سایت، طرح‌های ذخیره‌شده، درخواست‌ها و اطلاعات اتصال پیامک تغییر داده نمی‌شوند. اطلاعات آزمون فقط در دیتابیس جدا ساخته می‌شود.

در بازآزمایی با لید و فرصت فروش ثبت‌شده، دو ایراد نیز اصلاح شدند: عرض جدول و کانبان به محدودهٔ خودشان مقید شد تا صفحهٔ موبایل سرریز نکند؛ برچسب‌های مطلق دسترس‌پذیری کارت‌ها نیز به خود محدودهٔ اسکرول کانبان وابسته شدند. محتوای جدول تب‌های غیرفعال CRM هنگام نمایش اعلان یا فرصت فروش محاسبه نمی‌شود. محاسبهٔ جدول نامربوط قبلاً می‌توانست تاریخ نامعتبر بخواند و صفحه را به وضعیت خطا ببرد. سناریوی آزمون، همهٔ تب‌ها را با دادهٔ واقعی دیتابیس آزمایشی باز می‌کند و خطاهای جاوااسکریپت را بررسی می‌کند.

قبل از تغییر، شمار و checksum داده‌ها در `qa/admin-unified/database-before.json` ثبت و تصویر وب فعال با نام `makan-admin-unified-before:20261026` نگه‌داری شد. این ثبت checksum، پشتیبان دیتابیس محسوب نمی‌شود؛ این تغییر به Migration نیاز ندارد.

## فایل‌های اصلی

- `apps/web/src/features/admin/page-kit.tsx` و `admin-shell.tsx`: هدر، سطح محتوا، شمارها و محدودهٔ یکپارچهٔ مدیریت.
- `apps/web/src/styles/admin-unified.css` و اتصال آن در `globals.css`: قواعد مشترک محدود به مدیریت، فرم‌ها، تب‌ها، جدول‌ها، پنجره‌ها و ابزارهای صفحه‌ساز.
- صفحه‌های داشبورد، ورود، آمار، درخواست‌ها و جزئیات، خطا و دسترسی غیرمجاز زیر `apps/web/src/app/admin`.
- اجزای ویرایش محتوا و نسخه‌ها، آموزش، کتابخانهٔ طراحی، پروندهٔ مشتری، CRM، رسانه و پنجره‌های ویرایش زیر `apps/web/src/features`.
- `apps/web/tests/v2/admin-unified.spec.ts` و فاز `admin-unified` در `scripts/run-v2-quality.py`.

## اجرای بررسی‌ها

```powershell
npm run lint
npm run typecheck
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py build --phase admin-unified
docker compose --env-file .env.test -f compose.test.yaml up -d --wait
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase admin-unified --spec admin-unified --project all
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase admin-unified --spec admin-refresh --project all
```

تصاویر دسکتاپ و موبایل و نتایج مرورگرها در `docs/qa/admin-unified` ثبت می‌شوند. آزمون خودکار دسترس‌پذیری جایگزین ممیزی دستی کامل نیست. اتصال به سرویس واقعی پیامک در این تغییر آزموده نمی‌شود؛ مشخصات آن حفظ می‌شود.

## نتیجهٔ تست‌ها

گزارش‌های نهایی ۴۹ آزمون موفق، بدون آزمون ناموفق، نادیده‌گرفته‌شده یا retry خودکار ثبت کرده‌اند:

| مجموعه | تعداد | پوشش |
| --- | --- | --- |
| `admin-unified` | ۹ | ورود، ۲۲ نمای مسیر و نوع محتوا، تب‌ها، فیلترها و پنجرهٔ CRM در Chromium، Firefox و WebKit |
| `admin-refresh` | ۲۱ | ۹ صفحهٔ مدیریت، دسته و برچسب، رسانه، تنظیمات، پیامک، حساب، Audit، OTP، MFA، کد بازیابی و لغو نشست در سه موتور مرورگر |
| `content-manager` | ۳ | ایجاد پیش‌نویس، بایگانی با تأیید، تاریخچه، فیلتر و صفحه‌بندی و پنجرهٔ ایجاد محتوا |
| `library` | ۳ | دسترسی متناسب با نقش، ساخت و ذخیرهٔ طرح و تنظیمات سراسری |
| `crm` | ۱ | لید، مدرسه، مخاطب، ارزیابی، جابه‌جایی کانبان، نتیجهٔ دمو، پیگیری و گزارش واقعی |
| `builder` | ۱ | بارگذاری، کشیدن عناصر، تنظیم موبایل، ذخیره و بازخوانی، انتشار، ثبت واقعی دمو و بازیابی نسخه |
| `learning` | ۱۱ | مقاله، Rich Text، تصویر، آپارات، مجموعه، وبلاگ، انتشار، حفاظت پیش‌نویس و دسترس‌پذیری مدیریت و جزئیات عمومی |

مقایسهٔ خودکار فونت، اندازه و وزن عنوان با صفحهٔ مرجع، بررسی سرریز در عرض‌های ۱۴۴۰، ۱۲۰۰، ۱۰۲۴، ۷۶۸، ۴۸۰ و ۳۶۰ پیکسل و axe در دسکتاپ و موبایل انجام شد. تصاویر نمونه: [داشبورد](qa/admin-unified/dashboard-desktop-chromium.png)، [ویرایش آموزش در موبایل](qa/admin-unified/learn-edit-article-mobile-chromium.png) و [کانبان در موبایل](qa/admin-unified/crm-view-%DA%A9%D8%A7%D9%86%D8%A8%D8%A7%D9%86%20%D9%81%D8%B1%D9%88%D8%B4-mobile-chromium.png).

آزمون صفحه‌ساز در اجرای نخست، یک بار هنگام دریافت توکن فرم به مهلت ۸ ثانیه رسید؛ پاسخ Backend موفق بود ولی درخواست مرورگر پیش از دریافت پاسخ پایان یافت. اجرای مجزای همان آزمون بدون تغییر فرم عمومی موفق شد و ثبت دمو در دیتابیس آزمایشی تأیید شد. گزارش اولیه در `attempt-builder-token-timeout.json` و نتیجهٔ نهایی موفق در `browser-v2-builder-chromium.json` محفوظ‌اند. گزارش `attempt-before-mobile-and-crm-fixes.json` مربوط به دور تشخیص ایرادهای رفع‌شدهٔ CRM است.

ESLint، TypeScript و ساخت Production وب موفق‌اند. لاگ بررسی کد در `qa/admin-unified/frontend-checks.log` ثبت شده است. هیچ Commit یا Push در این نوبت انجام نشده است.

## نسخهٔ فعال

ساخت Linux Docker موفق شد و نسخهٔ تازه روی `http://127.0.0.1:3100` فعال است. هر چهار سرویس `web`، `api`، `db` و `maintenance` در وضعیت `healthy` هستند. ۲۲ بررسی HTTP روی صفحات عمومی، مسیرهای مدیریت، سلامت، الزام ورود، منع API بدون حساب و ۴۰۴ موفق شد. وجود CSS مشترک تازه و تفکیک صفحهٔ مرجع در بستهٔ فعال کانتینر نیز بررسی شد.

شمار و checksum داده‌های CMS و حساب‌ها قبل و بعد برابرند؛ از جمله ۲۶ صفحه و ۵۰ نسخهٔ محتوا. مقایسهٔ مستقل هر ۹ جدول CRM نیز برابر بود. دادهٔ آزمایشی وارد محیط اصلی نشده است. رویدادهای قدیمی تا زمان ثبت مبنا مقایسه شدند؛ زمان آخرین ورود مدیر از مقایسه کنار گذاشته شد تا ورود طبیعی مدیر به‌عنوان تغییر محتوا تلقی نشود. نسخهٔ دیتابیس اصلی همان `0009_demo_crm` باقی ماند؛ Migration جدید یا اجرای Migration روی محیط اصلی انجام نشد.

گزارش نهایی: [verification.json](qa/admin-unified/verification.json). گزارش سلامت، نسخهٔ فعال، داده‌های قبل و بعد و لاگ ساخت در همان پوشه قرار دارند. شمارهٔ Build در [deployed-build.json](qa/admin-unified/deployed-build.json) ثبت شده است.

برای دیدن رابط تازه، صفحهٔ باز پنل را کامل تازه‌سازی کنید (`Ctrl+Shift+R`). دستور اجرای سایت در README همان دستور قبلی است؛ ساخت مالک دوباره یا ورود مجدد محتوای اولیه لازم نیست.

برای بازگرداندن صرفاً نسخهٔ قبلی رابط وب، از ریشهٔ پروژه:

```powershell
docker tag makan-admin-unified-before:20261026 makan-landing-dev-web:0.10.0
docker compose --profile website up -d --wait web
```

این بازگشت به حذف داده یا بازیابی دیتابیس نیاز ندارد. ساخت دوباره از سورس فعلی، رابط یکپارچهٔ تازه را برمی‌گرداند.
