# گزارش مرحله ۸ — فرم واقعی و CRM

دامنه این تحویل فقط Backend و وب‌سایت مستقل لندینگ ماکان است. مرحله ۷ با دستور کاربر تأیید شده و مرحله ۸ اجرا شده است؛ مرحله ۹ و انتشار Production هنوز آغاز نشده‌اند. سیاست ۱۸۰ روز و متن رضایت در همین گفت‌وگو صریحاً تأیید شدند. کد یا دیتابیس محصول اصلی ماکان تغییر نکرده است.

## تغییرات

- فرم‌های دمو و تماس با RHF/Zod، خطای فیلدی فارسی، آماده‌سازی توکن، رضایت اجباری، حالت ارسال، پیام موفق پس از commit، کد تصادفی و retry با حفظ ورودی فعال‌اند. آدرس‌ها و فیلدها مطابق سند باقی مانده‌اند؛ CTAهای CMS/آموزش منبع داخلی را به فرم منتقل می‌کنند.
- API مبتنی بر FastAPI/Pydantic به نسخه داخلی0.8.0 رسید و migration افزایشی `0006_leads` چهار جدول درخواست، رسید، یادداشت و تاریخچه را ایجاد می‌کند. هیچ ذخیره موقت یا API نمایشی در مسیر نهایی وجود ندارد.
- ارسال هم‌زمان با کلید یکسان یا کلیدهای متفاوت و محتوای همسان یک رکورد دارد؛ تغییر body با همان کلید 409، retry معتبر همان مرجع. HMAC، advisory lock و TTL واقعی PostgreSQL استفاده می‌شوند.
- کنترل Origin، توکن امضاشده، سقف شبکه و روش تماس مشترک بین workerها، honeypot و محدودیت body؛ لاگ و audit بدون متن/شماره فرم. مهمان401 و editor403؛ owner/sales مجازند. CSRF و If-Match در تغییرات پنل الزامی‌اند.
- `/admin/leads` با جست‌وجو، فیلتر نوع/وضعیت/منبع/مسئول/تاریخ، صفحه‌بندی، جزئیات، تعیین مسئول، نتیجه بسته‌شدن، یادداشت و تاریخچه پیگیری ساخته شده است. قرارداد فقط با نتیجه won دمو شمرده می‌شود؛ اعداد بر رکورد واقعی و بازه تعریف‌شده‌اند.
- پاک‌سازی batch پس از ۱۸۰ روز از آخرین پیگیری، حذف PII و یادداشت/رسید، حفظ آمار بی‌نام و audit. تاریخچه وضعیت مجوز UPDATE/DELETE برای runtime ندارد. سیاست backup و راه‌اندازی job روزانه در راهنمای عملیاتی ثبت شده‌اند.
- متن privacy/terms اولیه اصلاح و انتقال نسخه‌ای محافظت‌شده ساخته شده است؛ نسخه قدیمی و ویرایش انسانی حذف نمی‌شوند. سایر بندهای حقوقی پیش‌نویس باقی‌اند.

## بررسی‌های نهایی

| بررسی | نتیجه واقعی |
| --- | --- |

| پذیرش مرورگر Chromium/Firefox/WebKit | ۶۹ سناریو موفق؛ صفر شکست/skip/flaky |
| چیدمان تکمیلی فهرست CRM در سه موتور | ۳ سناریو موفق؛ نام بدون فاصله، فیلتر واقعی و عرض‌های ۳۶۰/۷۶۸/۱۴۴۰ |
| axe | ۱۳۵ بررسی، صفر violation؛ ۹۹ attachment و ۳۶ بررسی فرم/CRM |
| تصاویر QA | 84 تصویر؛ نمونه‌های موبایل/دسکتاپ بازبینی شده‌اند |
| Production Build / TypeScript / ESLint / Ruff | موفق؛ Node24، نسخه‌های lock موجود |

| ماندگاری و CLI | درخواست/یادداشت/تاریخچه/نتیجه/نشست/محتوا/رسانه پس از restart و recreate حفظ؛ purge با نقش runtime واقعی موفق |
| audit وابستگی runtime وب | صفر finding؛ ۹ finding high توسعه از advisory قبلی باقی است |

مجموع مرورگر ۷۲ سناریو است: اجرای ۶۹تایی پذیرش اصلی و اجرای ۳تایی فهرست CRM پس از اصلاح CSS همان مسیر. پس از اصلاح نهایی اندازه‌ها، Build/TypeScript/lint و همان چیدمان در هر سه موتور دوباره اجرا شدند؛ CSS محدود فهرست، جریان ثبت/احراز هویت را تغییر نمی‌دهد. آزمون‌ها API/DB واقعی مستقل دارند؛ تنها429 در یکی از تست‌های رابط fault injection است و 429 مشترک واقعی در PostgreSQL جدا بررسی شده است. سناریوی پاسخ گم‌شده پس از commit و422 از سرویس واقعی هستند. تصاویر full-page پس از تعامل ممکن است فوکوس فعال یا header چسبان در موقعیت scroll آزمون داشته باشند؛ اندازه و عدم سرریز مستقلاً بررسی شده‌اند. این نتایج جایگزین آزمون Lighthouse یا گواهی کامل WCAG نیستند.

اجرای اولیه import اشتباه UUID4، انتظار جدول‌های قدیمی، مقایسه JSON خام با schema، اتصال label، رقابت navigation پس از خروج و انتخاب alert عمومی Next را آشکار کرد؛ اصلاح و بررسی مجدد شدند. Docker نیز نیاز UPDATE برای قفل‌گذاری رسید در purge را یافت؛ مجوز اصلاح شد و آزمون نگهداری با نقش runtime اجرا می‌شود. بررسی نام بلند، سرریز موبایل و متن در inline-flex WebKit را یافت؛ تشخیص اندازه‌ها در webkit-overflow-diagnostic.json و اصلاح جریان متن/اندازه grid ثبت است. انتقال محتوای توسعه تفاوت فیلد اختیاری faq_slugs در نسخه قدیمی را یافت؛ نرمال‌سازی دو طرف و آزمون نسخه قدیمی اضافه شدند. اجرای ناموفق یا متوقف موفق شمرده نشده و خلاصه‌های قبل اصلاح در QA باقی‌اند.

محیط توسعه اکنون API0.8.0/schema0006_leads و ۱۱۱ مسیر OpenAPI دارد؛ ۲۶ محتوا/۲۹ revision با حفظ تاریخچه، صفر مدیر/درخواست/رسانه ساختگی در زمان ثبت شاهد. فرمان انتقال متن فقط privacy/terms دست‌نخورده را به revision تازه رساند؛ پاک‌سازی روی محیط خالی موفق و شمارش صفر بود. تست‌ها هیچ داده‌ای به دیتابیس اصلی اضافه نکردند. Volume اصلی و فرایند dev کاربر روی3000 حفظ شدند؛ fixtureهای آزمون پس از استفاده حذف می‌شوند.

## محدودیت‌های باقی‌مانده

انتشار Production در این مرحله تأیید نمی‌شود. HTTPS، reverse proxy و تفکیک IP مورد اعتماد، زمان‌بندی روزانه purge، انقضای backup و راه حذف زودهنگام با احراز هویت باید در مرحله۱۰ تکمیل شوند. سقف شبکه فعلی BFF از نشانی مشترک Next استفاده می‌کند و ممکن است در شبکه‌های بزرگ نیازمند تنظیم باشد.

حساب مدیر واقعی و مسئول مشخص توسط مالک ساخته/تعیین می‌شوند؛ مدیر یا درخواست ساختگی در دیتابیس توسعه seed نشده است. کانال رسمی و تعهد پاسخ ارائه نشده، بنابراین وعده تماس در زمان معین یا ارسال ایمیل/SMS وجود ندارد. نبود provider مانع ثبت واقعی نیست. analytics بازدید/خطای فرم، SEO نهایی و Lighthouse مرحله۹؛ راه‌اندازی کامل Compose وب/proxy/CI مرحله۱۰.

پخش واقعی ویدیوی مجاز آپارات از مرحله۷ همچنان بدون تأیید نهایی باقی است. audit وابستگی runtime وب صفر finding دارد؛ ۹ finding توسعه از advisory قبلی braces باقی‌اند و راه‌حل ناسازگار تحمیل نشده است. تغییر خودکار `apps/web/next-env.d.ts` از قبل موجود بود و از commit این مرحله کنار گذاشته می‌شود.

## تحویل

فهرست دقیق فایل‌های ایجاد/ویرایش/حذف در `docs/step-8-changed-files.md` ثبت شده است. شواهد آزمون و نتایج اجرای ناموفق/اصلاح‌شده در QA مرحله۸ جدا از مراحل قبلی نگهداری می‌شوند. قبل از commit گزارش تغییرات ارائه می‌شود؛ commit محلی فقط پس از موفقیت بررسی‌ها، بدون Push. پایان مرحله۸ توقف برای تأیید مرحله۹ است.
