# امنیت و شرایط انتشار

کلیدهای session، MFA، edge و backup مستقل‌اند. مدیران از کاربران اپلیکیشن جدا هستند؛ MFA اختیاری هر مدیر، کد بازیابی، CSRF/Origin و cookie Secure/HttpOnly/SameSite=Lax فعال‌اند. مجوزها سمت سرور و audit حساس append-only است. سمت proxy ورودی‌های جعلی IP/کلید با مقدار مشاهده‌شده و کلید داخلی جایگزین می‌شوند؛ API هدرهای استاندارد forwarding را اعتماد نمی‌کند. quota در PostgreSQL بین processها مشترک است.

ورود جاری مدیران فقط با شماره همراه ثبت‌شده و OTP است. ساخت مالک با `python -m app.commands.admin bootstrap` و اتصال حساب قبلی با `bind-phone --email` انجام می‌شود؛ شماره در prompt دریافت می‌شود. دیباگ111111 فقط development/test است و تولید آن را اجباری خاموش می‌کند. حساب ساخته‌شده از درخواست عمومی کد ایجاد نمی‌شود. کد HMAC، محدودیت تلاش، انقضا و اتصال به مرورگر دارد؛ MFA فعال بعد از OTP نیز الزامی است. جزئیات اتصال ملی‌پیامک و CLI خصوصی پیکربندی آن در [README](../README.md) آمده است. نام کاربری و رمز وب‌سرویس رمزگذاری می‌شوند و API تنظیمات فقط وضعیت اتصال را می‌دهد. تغییر حساس پنل به کد جدید همان نشست نیاز دارد. پس از restore تمام OTPهای قبلی باطل می‌شوند.

سیاست CSP صفحه با nonce واقعی، strict-dynamic، بدون unsafe-eval تولید می‌شود. JSON-LD هم nonce دارد. iframe فقط مسیر ویدیو/preview آموزش و دامنه رسمی آپارات است؛ HTML دلخواه embed پذیرفته نیست. style-inline به‌دلیل اجزای editor/UI مجاز است. اجرای شخص ثالث از consent آنالیتیکس مستقل است. پخش بیرونی ویدیو فقط با کنش کاربر آغاز می‌شود.

HSTS یک‌سال بدون preload/includeSubDomains، nosniff، Referrer same-origin، X-Frame DENY و Permissions-Policy محدود شده‌اند. Caddy admin خاموش است. برای CDN آینده اعتماد به IP CDN را بدون allowlist و آزمون دوباره فعال نکنید. secrets در محیط runtime و metadata Docker برای اپراتور میزبان قابل مشاهده‌اند؛ root میزبان و Docker socket مرز امنیتی‌اند. فایل env را محدود و کپی‌های موقت/CI را محافظت کنید.

اسکن‌ها باید روی **image نهایی** اجرا شوند؛ Node/Python runtime و OS هر دو مهم‌اند. خروجی کامل scan در `docs/qa/step10` نگهداری می‌شود. آسیب‌پذیری‌های بدون patch یا ناسازگار با مسیر کاربردی باید با منبع رسمی، scope و موعد بازبینی ثبت شوند؛ شمار صفر ساختگی یا ignore گسترده مجاز نیست. CI gate Critical مانع انتشار یافته Critical جدید می‌شود؛ High قابل اصلاح نیز قبل از انتشار اصلاح شود. scanner نتیجه را بر مبنای DB همان زمان می‌دهد، تضمین دائمی امنیت نیست.

برای رخداد، زمان/شناسه درخواست بی‌نام را ثبت، نشست‌های مدیر را لغو و secrets مربوط را rotate کنید. متن فرم، رمز، cookie و اطلاعات شخصی در گزارش عمومی یا access log ثبت نشوند. API فقط فیلدهای log مجاز دارد و access log خام خاموش است؛ Caddy access log فعال نشده است. log تشخیصی میزبان همچنان خصوصی است. پس از restore نشست‌های قدیمی ابطال می‌شوند و retention پیش از اتصال عمومی اجرا می‌شود.

پیش از انتشار نهایی بررسی حقوقی متن حریم خصوصی/شرایط، اطلاعات تماس واقعی، لوگو/تصاویر محصول تأییدشده و منابع آموزش لازم‌اند. آنالیتیکس خاموش‌بودن پیش‌فرض و احترام به GPC/DNT در مرحله۹ حفظ شده است. PostgreSQL نباید به اینترنت expose شود. backup حاوی داده شخصی رمز‌شده است و سیاست نگهداری آن باید جدا تصویب شود.

## اصلاح image و استثنای محدود

ابزارهای نصب npm/yarn و pip از runtime حذف می‌شوند؛ build stage آن‌ها را حفظ می‌کند. پایه برنامه‌ها به Debian13 منتقل شده و بسته‌های لازم سیستم حفظ می‌شوند؛ API فقط PostgreSQL را می‌پذیرد. آسیب‌پذیری CVE-2023-45853 برای نسخه مشخص zlib1g bookworm با PURL محدود و انقضا ۱۳نوامبر۲۰۲۶ مستثنی شده است، چون Debian کد contrib/minizip آسیب‌پذیر را در آن binary نمی‌سازد؛ نتیجه خام و suppressed حفظ می‌شوند. [منبع رسمی Debian](https://security-tracker.debian.org/tracker/CVE-2023-45853). Caddy2.11.7 با Go1.27.2 و x/net0.60.0 بازسازی می‌شود؛ checksum moduleها با Go sumdb فعال می‌ماند. [روش رسمی xcaddy](https://github.com/caddyserver/xcaddy).

اعتبارسنجی Client با Zod jitless پیش از ساخت schema انجام می‌شود تا CSP به تولید کد پویا نیاز نداشته باشد. [راهنمای رسمی Zod](https://zod.dev/compile). bridge برای POST رسانه۳۰ثانیه و برای سایر درخواست‌ها۱۲ثانیه انتظار دارد؛ پراکسی API۳۰ثانیه، SQL runtime۳ثانیه است.
