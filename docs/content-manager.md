# بازطراحی مدیریت محتوای سایت

## محدوده

رابط مسیر `/admin/content` با هویت بصری آبی ماکان و کتابخانهٔ طراحی هماهنگ شده است. APIها، احراز هویت، ساختار محتوا، پیش‌نویس و انتشار، نسخه‌ها و بایگانی موجود حفظ شده‌اند. Migration، CMS یا سرویس جدیدی ایجاد نشده است.

## تجربهٔ جدید

- فهرست محتوا نقطهٔ اصلی صفحه است؛ فرم ساخت از بالای فهرست به پنل کناری منتقل شده است.
- ردیف‌ها در دسکتاپ ستون‌های تراز عنوان/نوع، وضعیت، تاریخ و عملیات دارند. در موبایل، اطلاعات هر ردیف زیر هم قرار می‌گیرند و عملیات همیشه در دسترس است.
- هر نوع محتوا آیکون مشخص دارد. وضعیت با متن و نشان رنگی نمایش داده می‌شود؛ برای فهم وضعیت به رنگ به‌تنهایی وابسته نیستیم.
- جست‌وجوی عنوان و نوع، و دکمه‌های وضعیت از فیلتر واقعی API موجود استفاده می‌کنند. شمارش، محدودهٔ موارد نمایش‌داده‌شده و صفحه‌بندی از پاسخ سرور می‌آیند.
- فیلترهای اعمال‌شده از مقادیر در حال تایپ جدا هستند؛ زدن صفحهٔ بعد، جست‌وجویی را که هنوز تأیید نشده اعمال نمی‌کند. تغییر وضعیت یا اعمال فیلتر از صفحهٔ اول آغاز می‌شود.
- ویرایش و پیش‌نمایش در هر ردیف، و تاریخچه/بایگانی در منوی سه‌نقطه قرار دارند. بایگانی نیازمند تأیید صریح و نسخهٔ معتبر همان رکورد است؛ تاریخچه حذف نمی‌شود.
- ساخت صفحه، صفحهٔ اصلی، معرفی امکان، مخاطب و پرسش متداول با همان قرارداد موجود انجام می‌شود. نوع غیر FAQ به بوم صفحه‌ساز هدایت می‌شود؛ FAQ ویرایشگر خود را حفظ می‌کند.
- خطای سرویس داخل پنل ساخت نمایش داده می‌شود و عنوان و آدرس واردشده حفظ می‌شوند. پنل با Escape بسته می‌شود و تمرکز به دکمهٔ بازکننده برمی‌گردد.

## فایل‌های این تغییر

- `apps/web/src/features/cms/content-list.tsx`: رابط فهرست، فیلتر، صفحه‌بندی و پنل ساخت.
- `apps/web/src/features/cms/content-row.tsx`: ردیف واکنش‌گرا، وضعیت، آیکون نوع و منوی عملیات.
- `apps/web/src/styles/content-manager.css` و `globals.css`: جزئیات چیدمان محدود به همین صفحه.
- `apps/web/tests/v2/content-manager.spec.ts`: پذیرش واقعی ساخت، نگهداری پیش‌نویس، بایگانی، فیلتر، صفحه‌بندی، خطای تکرار آدرس، موبایل و دسترس‌پذیری.
- آزمون‌های `builder.spec.ts`، `elementor.spec.ts`، `studio.spec.ts` و `e2e/cms.spec.ts`: هماهنگی تعامل ساخت محتوا با دکمهٔ جدید.
- `scripts/run-v2-quality.py`: جداسازی شواهد این تغییر در فاز `content-manager`.
- `README.md`: راهنمای کوتاه استفاده از صفحه.

## روش بررسی

آزمون مرورگر با PostgreSQL مجزا و API واقعی اجرا می‌شود. داده‌های صفحه‌بندی صرفاً در دیتابیس آزمون ساخته می‌شوند؛ دادهٔ نمونه‌ای به سایت اصلی افزوده نمی‌شود. تصاویر دسکتاپ و موبایل و گزارش‌ها در `docs/qa/content-manager` نگهداری می‌شوند.

```powershell
npm run lint
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py build --phase content-manager
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase content-manager --spec content-manager --project all
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase content-manager --spec builder --project chromium
```

قرارداد API و Migrationها تغییر نکرده‌اند. Commit و Push انجام نشده است. ارزیابی خودکار دسترس‌پذیری، جای آزمون دستی با صفحه‌خوان را نمی‌گیرد. وضعیت فیلترها همانند نسخهٔ قبلی در URL ذخیره نمی‌شود.

## نتیجهٔ نهایی

- Build تولید، TypeScript و ESLint موفق بودند؛ Diff و تنظیمات Compose نیز بررسی شدند.
- ۹ اجرای پذیرش مدیریت محتوا در Chromium، Firefox و WebKit و یک اجرای مسیر کامل صفحه‌ساز در Chromium موفق شدند؛ گزارش‌های نهایی شکست، مورد اجرا‌نشده یا Retry ندارند.
- تصویر Docker ساخته و روی پورت ۳۱۰۰ اجرا شد؛ حضور کد جدید در Bundle سرویس فعال بررسی شد.
- هر چهار سرویس سالم‌اند؛ ۹ بررسی HTTP شامل حفاظت مسیر مدیریت محتوا موفق شدند.
- شمارش و Checksum برگه‌ها، نسخه‌ها، رسانه‌ها و درخواست‌ها با قبل برابر است؛ ۲۶ برگه و ۵۰ نسخه حفظ شده‌اند و Migration همان `0009_demo_crm` است.
- گزارش ماشینی در `docs/qa/content-manager/verification.json` و تصاویر همان پوشه قرار دارند.
