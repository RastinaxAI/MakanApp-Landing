# تصمیم‌ها و معیار پذیرش CMS — مرحله ۶

کاربر شروع STEP6 را مجاز کرده است. دامنه: مدیریت صفحات/سکشن، امکانات، مخاطبان، FAQ دسته‌دار، تنظیمات عمومی و SEO، رسانه و اتصال واقعی صفحات عمومی؛ مقاله/آپارات/مجموعه مرحله۷ و CRM مرحله۸ هستند.

موتور انتشار Page/PageRevision موجود حفظ می‌شود؛ همه محتوای معرفی از همین موتور با page_type و slug داخلی namespaced استفاده می‌کند. چهار جدول مستقل feature/audience/faq revision با رفتار یکسان ساخته نمی‌شوند: تکرار منطق انتشار، قفل، audit و رسانه کاهش می‌یابد؛ قراردادهای Pydantic مستقل هر نوع و endpointهای مستقل عمومی/مدیریتی حفظ می‌شوند. نوع و slug بعد اولین انتشار ثابت‌اند؛ archive به‌جای حذف سابقه. سکشن‌ها جدول FK واقعی به revision دارند؛ reference رسانه یک FK واقعی به همان revision دارد و رابطه پلی‌مورفیک آزاد نداریم. FAQ category جدول مستقل دارد و ارتباط آن با revision FK است.

نسخه جدید snapshot immutable است؛ ویرایش revision جدید می‌سازد و If-Match/row_version از lost update جلوگیری می‌کند. public query فقط نسخه published یا scheduled رسیده را می‌خواند؛ شروع schedule روی snapshot مشخص است و ویرایش‌های بعدی روی آن اثر ندارند. انتشار فوری schedule قبلی را لغو می‌کند؛ preview احراز هویت/مجوز/no-store/noindex دارد. هیچ job یا clock مرورگر مسئول درست‌بودن انتشار نیست؛ زمان UTC سرور مرجع است.

Rich text با Tiptap و sanitizer سرور nh3؛ HTML/style/iframe فعال و URL اجرایی حذف می‌شوند. تصویرهای HTML فقط مسیر ثابت رسانه داخلی و reference FK معتبر دارند. Pillow تصویر را decode/re-encode، EXIF را حذف و pixel/size/MIME را محدود می‌کند. SVG و ویدیو خام قبول نمی‌شود. upload ابتدا private؛ public شدن تنها هنگام publication reference مجاز یا تصمیم صریح مدیر است و بعد عمومی‌شدن، خصوصی‌شدن دوباره ادعای محرمانگی ایجاد نمی‌کند. فایل‌ها اسم UUID دارند، جای اصلی خارج web/public است و volume مستقل دارند.

محتوای تألیف‌شده مرحله۳ از سورس به manifest import منتقل می‌شود؛ fallback hardcode عمومی نخواهیم داشت. واردکردن متن واقعیِ موجود با CLI console و audit منبع انجام می‌شود؛ حساب پیش‌فرض ساخته نمی‌شود. created_by برای import سیستمی nullable خواهد بود؛ تمام ویرایش‌های HTTP مدیر واقعی دارند. واردکننده idempotent محتوای موجود یا ویرایش مدیر را overwrite نمی‌کند. آماده‌بودن پیام‌رسان/مدرسه/گزارش بر اساس تأیید مستقیم پیشین و AI برچسب roadmap حفظ می‌شود. متن حقوقی همچنان draft حقوقی، سایت noindex و assetهای رسمی ناموجود placeholder مشخص‌اند.

پذیرش: PostgreSQL migration تازه/قبلی و drift/grants؛ CRUD/filter/pagination و 401/403/CSRF؛ snapshot draft/private، زمان UTC، stale409 و audit rollback؛ XSS و لینک ناسالم؛ رسانه spoof/حجم/pixel/path/delete-reference؛ persistence restart؛ ویرایش از UI بدون JSON/کدنویسی → preview خصوصی → publish → SSR واقعی/metadata جدید؛ build/lint/typecheck، Pytest/HTTPX، Playwright سه موتور و axe. گیت‌ها و محدودیت‌ها در گزارش نهایی ثبت می‌شوند. STEP7 به تأیید تازه وابسته است؛ Push مجاز نیست.
