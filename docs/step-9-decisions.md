# تصمیم‌های مرحله ۹ — SEO و عملکرد

مرجع: سند نسخه ۱٫۱، بخش‌های ۳، ۱۲ و ۱۲الف؛ درخواست کاربر برای اجرای مرحله ۹. دستور انتشار یا شروع مرحله ۱۰ دریافت نشده است.

- ایندکس عمومی دو شرط مستقل دارد: `SEO_INDEXING_ENABLED=true` در تنظیمات استقرار و دامنه HTTPS معتبر در تنظیمات CMS. هر نسخه محتوا نیز باید `seo.indexable=true` باشد. حالت پیش‌فرض بسته است.
- sitemap از همان نسخه مؤثر عمومی ساخته می‌شود: انتشار زمان‌بندی‌شده فقط پس از موعد، بدون draft، بایگانی، محتوای مخفی، FAQ مستقل، صفحه کم‌محتوا یا صفحات داخلی. URLها به گروه صفحات و آموزش تقسیم و در قطعات ۱۰۰۰تایی ارائه می‌شوند.
- canonical از دامنه تنظیم‌شده و مسیر اصلی ساخته می‌شود؛ queryهای جست‌وجو، source و series وارد canonical نمی‌شوند. صفحات فیلترشده کتابخانه noindex هستند.
- HTML و داده‌های عمومی در هر درخواست از PostgreSQL خوانده می‌شوند؛ React cache فقط درخواست‌های تکراری همان رندر را حذف می‌کند. cache پایدار برای نسخه مؤثر، بدون سازوکار invalidation قابل اثبات، فعال نمی‌شود؛ انتشار یا لغو انتشار نباید دیر اعمال شود.
- JSON-LD فقط بر داده واقعی CMS و متن قابل مشاهده متکی است؛ بدون امتیاز، قیمت، لوگوی اختراعی یا تاریخ ویدیو حدسی. VideoObject بدون تاریخ معتبر آپلود ساخته نمی‌شود. escape علامت `<` مانع خروج از script می‌شود.
- هشت رویداد تجاری سند با allowlist، رضایت اختیاری، شناسه نشست روزانه HMAC و نگهداری محدود پیاده‌سازی می‌شوند. نام، تلفن، ایمیل، متن فرم، URL کامل، query، referrer خام، IP و user-agent ذخیره نمی‌شوند. سیاست opt-in توسط کاربر تصویب شد؛ فعال‌سازی جمع‌آوری عمومی در پیکربندی انتشار انجام می‌شود؛ رضایت فرم مرحله ۸ جای آن را نمی‌گیرد.
- آمار آزمایشی فقط در دیتابیس مستقل آزمون ساخته می‌شود. نرخ تبدیل آنالیتیکس مربوط به بازدیدکنندگان رضایت‌داده است؛ آمار CRM کل درخواست‌ها را پوشش می‌دهد. صفر مخرج به صورت null نمایش داده می‌شود.
- شرایط Lighthouse: build تولید، مرورگر و نسخه ثابت، cold cache، mobile/simulated throttling، سه اجرا برای هر مسیر؛ همه نتایج ذخیره می‌شوند. نبود staging HTTPS و محتوای واقعی مقاله/ویدیو در گزارش از آزمون محلی با fixture تفکیک می‌شود. INP میدانی با تست آزمایشگاهی اثبات نمی‌شود.

پذیرش: آزمون انتشار/زمان‌بندی/حریم خصوصی/دسترسی API روی PostgreSQL، HTML و metadata و schema و sitemap در مرورگر، تست رضایت و رویدادها، lint/typecheck/build، Lighthouse و ثبت محدودیت‌ها. دامنه و staging هنوز اعلام نشده‌اند.

پاسخ کاربر در همین مرحله: «آنالیتیکس داخلی با رضایت اختیاری؛ دامنه را بعداً اعلام می‌کنم». سیاست opt-in تصویب شد؛ نگهداری ۳۰ روز به عنوان تصمیم اجرایی محدود و قابل تغییر مستند است. فعال‌سازی جمع‌آوری عمومی و ایندکس برای پیکربندی انتشار باقی می‌ماند. policy_version در هر درخواست و تاریخ انقضای انتخاب مرورگر بررسی می‌شود.

برای RUM، هر document/نشست/شاخص یک رکورد دارد. گزارش‌های بعدی همان شاخص با شماره ترتیبی به‌روزرسانی می‌شوند؛ مقدار قدیمی یا درخواست دیررس جای مقدار نهایی را نمی‌گیرد. مجوز UPDATE نقش runtime فقط روی مقدار و شماره گزارش است. ناظرهای web-vitals پس از رضایت و یک‌بار برای document نصب می‌شوند؛ در لغو اجازه ارسال متوقف می‌شود. مسیر اولیه document ثبت می‌شود تا metric یک سند به مسیر بعدی SPA نسبت داده نشود.

اصلاح مبتنی بر اندازه‌گیری: دور اول Lighthouse افت median صفحه خانه۷۸، دمو۸۹ و ویدیو۸۱ و CLS ناشی از popup/font را نشان داد. رضایت در SSR از کوکی preference بدون شناسه خوانده می‌شود، نمایش اولیه ثابت است و فونت محلی display=optional دارد؛ شبکه کند از fallback خوانا استفاده می‌کند و فونت دیررس در همان بازدید جای متن را عوض نمی‌کند. عنوان سطح۲ برای گروه کارت‌ها افزوده شد و favicon صریحاً موقت است. هیچ نشان نهایی اختراع نشده است. همه دورها محفوظ‌اند.

Qualified view نیز به همان رضایت اختیاری متصل شد؛ mode disabled، رضایت غایب/نامعتبر، DNT/GPC مانع شمارش هستند. API POST به consent=true و policy_version معتبر نیاز دارد. در صورت لغو اجازه، timer/درخواست مرورگر متوقف می‌شود؛ nonce ربات/Origin/۲۰ثانیه/dedupe قبلی حفظ شده‌اند. پنج تست جدید این شرط را بررسی می‌کنند.

مهلت provisioning دیتابیس مستقل تست برای DDL از مهلت API جدا و ۳۰ثانیه است؛ API همچنان statement timeout سه‌ثانیه‌ای دارد. خطای قبلی CREATE INDEX در VM ثبت و suite بدون skip دوباره اجرا شده است.

دکمه‌ها پس از hydration تغییر opacity انیمیشنی ندارند؛ transition فقط رنگ، پس‌زمینه، border و shadow را پوشش می‌دهد. خطای گذرای کنتراست۳٫۰۳ در WebKit ثبت شد. تست layout اکنون دسته واقعی مستقل خود را می‌سازد تا کنترل ویرایش/حذف در اجرای متمرکز هم حضور داشته باشد. بررسی مجدد: `scripts/test-web-admin.ps1 -LearningLayoutOnly -BrowserProject chromium` و همان فرمان برای firefox؛ WebKit با `-Step9Acceptance -BrowserProject webkit` اجرا می‌شود.

میانه خانه در دور بازبینی بعدی۸۹ بود. Lighthouse بارگیری Zod بلااستفاده در خانه را ثبت کرد؛ واردکردن فرم از PublicPage عمومی حذف و composition آن فقط در route دمو و تماس انجام شد. HTML و عملکرد فرم حفظ می‌شوند، سایر صفحات بسته اعتبارسنجی فرم را دریافت نمی‌کنند. build و صفحات عمومی سه مرورگر، SEO/رضایت و Lighthouse پس از این اصلاح تکرار می‌شوند؛ تمام raw reportها باقی‌اند.
