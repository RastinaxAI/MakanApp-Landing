# بازطراحی صفحات مدیریت — ۲۶ اکتبر ۲۰۲۶

این تغییر روی همان پنل موجود انجام شده است. ورود پیامکی، MFA اختیاری، نقش‌ها، APIها، محتوا و اطلاعات قبلی حفظ شده‌اند. هدف، خلوت‌کردن فرم‌ها، ترازکردن اجزا، خوانایی فهرست‌ها و استفادهٔ راحت‌تر روی موبایل است.

## تغییر صفحات

| مسیر | تغییر |
| --- | --- |
| `/admin/learn` | تب‌های مقاله، ویدیو، مجموعه و وبلاگ؛ فیلتر عنوان و وضعیت، ردیف‌های خواناتر، نمایش وضعیت انتشار و لینک ایجاد متناسب با نوع محتوا |
| `/admin/learn/taxonomy` | جداسازی ویرایشگر از فهرست، جست‌وجوی دسته و برچسب، نمایش بخش آموزش یا وبلاگ، تأیید حذف |
| `/admin/media` | کتابخانهٔ تصویری، جست‌وجو و فیلتر دسترسی، پنجرهٔ بارگذاری با انتخاب یا رهاکردن فایل، ویرایش مشخصات و تأیید حذف |
| `/admin/faq-categories` | فرم جمع‌وجور کنار فهرست، جست‌وجو، ترتیب نمایش و تأیید حذف دسته |
| `/admin/accounts` | فهرست سازگار با موبایل، نمایش نقش و وضعیت، افزودن مدیر و تأیید تغییرات حساس در بخش مشخص |

| `/admin/audit` | نمایش خط زمانی رویدادها، عنوان فارسی همراه کد فنی، جست‌وجو در صفحه و صفحه‌بندی |
| `/admin/security` | خلاصهٔ وضعیت امنیت، گروه‌بندی تأیید پیامکی و MFA و فهرست نشست‌های قابل لغو |

هدر، مسیر صفحه، آیکون مربع با گوشهٔ گرد، فاصله‌ها، پیام نتیجه و حالت فهرست خالی در همهٔ این صفحات هماهنگ‌اند. رنگ آبی برند و فونت فارسی موجود حفظ شده‌اند. چیدمان در نمایشگر بزرگ دو ستون دارد و در موبایل به یک ستون تبدیل می‌شود.

## اصلاح رفتارهای موجود

- فیلتر عنوان و وضعیت آموزش با رفتن به صفحهٔ بعد حفظ می‌شود.
- خواندن دسته‌ها و برچسب‌های آموزش و وبلاگ با قرارداد موجود حفظ شده است؛ ذخیره و بازخوانی هر دو بخش در تست مرورگر بررسی می‌شود.
- پس از ایجاد مدیر، آخرین صفحهٔ فهرست نمایش داده می‌شود تا حساب تازه در ترتیب زمانی API قابل مشاهده باشد؛ جست‌وجوی قبلی پاک می‌شود.
- حذف دستهٔ پرسش متداول نیاز به تأیید دارد.
- بارگذاری تصویر در پنجرهٔ جداست. تست‌های قبلی رسانه متناسب با این جریان به‌روز شده‌اند.

جست‌وجوی آموزش سمت سرور است. جست‌وجوی مدیران، رسانه‌ها و رویدادها روی موارد صفحهٔ باز انجام می‌شود و این محدودیت در رابط مشخص است. جست‌وجوی دسته‌ها و برچسب‌ها روی کل فهرست دریافت‌شده انجام می‌شود.

## استفاده

سایت محلی روی `http://127.0.0.1:3100` اجرا می‌شود. با حساب مجاز وارد شوید و صفحهٔ موردنظر را از منوی سمت راست باز کنید. برای بارگذاری رسانه «افزودن تصویر» را بزنید؛ پس از انتخاب فایل و نوشتن متن جایگزین، بارگذاری را تأیید کنید. برای تغییر حساب، MFA یا مشخصات پیامک، ابتدا در همان صفحه کد تأیید تغییرات بگیرید.

اطلاعات واقعی ملی‌پیامک در این تغییر ثبت یا جایگزین نشده‌اند. آزمون ذخیرهٔ مشخصات روی دیتابیس آزمایشی جدا انجام می‌شود؛ اتصال به سرویس پیامکی واقعی بدون اطلاعات معتبر آزموده نمی‌شود.

## فایل‌ها و قراردادها

- اجزای مشترک: `apps/web/src/features/admin/page-kit.tsx` و `apps/web/src/styles/admin-pages.css`؛ اتصال سبک در `styles/globals.css`.
- صفحات مدیریت: `features/learning/admin.tsx`، `learning/taxonomy.tsx`، `cms/media-panel.tsx`، `cms/categories-panel.tsx`، `cms/settings-panel.tsx`، `admin/accounts-panel.tsx`، `admin/sms-panel.tsx`، `admin/security-panel.tsx`، `admin/otp-confirmation.tsx` و `admin/audit-panel.tsx`.
- اتصال سرور: `app/admin/(protected)/learn/page.tsx` و `audit/page.tsx`؛ دریافت دادهٔ صفحهٔ taxonomy از همان API موجود است.
- تست: `tests/v2/admin-refresh.spec.ts`، اصلاح مرحلهٔ بازکردن بارگذاری در `tests/v2/builder.spec.ts` و `tests/e2e/cms.spec.ts`؛ افزودن فاز و گزینهٔ اجرای تست به `scripts/run-v2-quality.py`.
- قرارداد API، Backend، مدل و Migration جدیدی اضافه یا تغییر نکرده است.

مسیرهای بالا نسبت به `apps/web/src` یا `apps/web` هستند. تغییرات صفحه‌ساز و مدیریت محتوای مراحل قبلی در همین درخت کاری حفظ شده‌اند. Commit و Push انجام نشده‌اند.

## بازتولید بررسی‌ها

از ریشهٔ پروژه و با پیش‌نیازهای تست موجود:

```powershell
npm run lint
npm run typecheck
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py build --phase admin-refresh
docker compose --env-file .env.test -f compose.test.yaml up -d --wait
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase admin-refresh --spec admin-refresh --project all
```

این ابزار برای تست مرورگر، API و دیتابیس موقت جدا می‌سازد؛ اطلاعات محیط اصلی را جایگزین نمی‌کند. تصاویر دسکتاپ و موبایل و گزارش مرورگرها در `docs/qa/admin-refresh` ذخیره می‌شوند.

## نتایج بررسی

- ESLint، TypeScript و ساخت Production وب موفق شدند.
- ۲۱ آزمون روی Chromium، Firefox و WebKit موفق شدند؛ صفر خطا، صفر آزمون ردشده یا ناپایدار. گزارش نهایی: `qa/admin-refresh/browser-v2-admin-refresh-all.json`.
- آزمون مستقل صفحه‌ساز در Chromium موفق شد: بارگذاری واقعی تصویر، ساخت محتوای تودرتو، تنظیم موبایل، ذخیره و بازخوانی، انتشار فرم واقعی دمو و بازیابی نسخه. گزارش: `qa/admin-refresh/browser-v2-builder-chromium.json`.
- در هر مرورگر، هر ۹ صفحه در عرض‌های ۱۴۴۰، ۱۲۰۰، ۱۰۲۴، ۷۶۸، ۴۸۰ و ۳۶۰ پیکسل بدون سرریز افقی بررسی شدند. آزمون خودکار axe روی دسکتاپ و موبایل نقضی در قواعد انتخاب‌شدهٔ WCAG A/AA و 2.2 AA گزارش نکرد؛ این نتیجه جایگزین ممیزی دستی کامل دسترس‌پذیری نیست.
- آزمون‌ها ذخیره و بازخوانی تنظیمات، محفوظ‌ماندن مشخصات محرمانهٔ پیامک، ایجاد و تغییر وضعیت حساب، ممنوعیت دسترسی ویرایشگر به مسیرهای مالک، ثبت رویداد، لغو نشست واقعی، راه‌اندازی MFA، ورود با کد بازیابی و غیرفعال‌کردن MFA را پوشش دادند.

تصاویر تست حاوی حساب‌ها و محتوای مخصوص دیتابیس آزمایشی‌اند؛ اطلاعات و محتوای فرضی وارد دیتابیس اصلی نشده است. گزارش `attempt-before-account-and-test-fixes.json` مربوط به دور اولیه و ناموفق پیش از اصلاح نمایش حساب تازه و خروج صریح در سناریوی تعویض حساب است؛ وضعیت نهایی را از دو گزارش موفق بالا بخوانید.

## نسخهٔ فعال و حفظ داده

ساخت Linux Docker و فعال‌سازی نسخهٔ جدید روی `http://127.0.0.1:3100` موفق شدند. هر چهار سرویس `web`، `api`، `db` و `maintenance` در وضعیت `healthy` هستند. ۱۸ بررسی HTTP شامل صفحات عمومی، هر ۹ مسیر مدیریت، الزام ورود، رد درخواست API بدون حساب و صفحهٔ ۴۰۴ موفق شدند. وجود کد رابط تازه، از جمله عنوان ورود پیامکی، در بستهٔ فعال داخل کانتینر نیز بررسی شد.

شمار و checksum داده‌های بررسی‌شدهٔ قبل و بعد برابرند: ۲۶ صفحه، ۵۰ نسخهٔ محتوا، حساب مدیر، تنظیمات سایت، دسته‌های پرسش متداول و سایر جدول‌های بررسی‌شده حفظ شدند. رویدادهای قبلی تا زمان ثبت مبنا مقایسه شدند و تغییر زمان آخرین ورود مدیر از مقایسه کنار گذاشته شد. نسخهٔ Migration همان `0009_demo_crm` است. مقایسه به‌تنهایی جایگزین پشتیبان دیتابیس نیست؛ در این تغییر Migration اجرا نشده است.

خلاصهٔ قابل بررسی: [verification.json](qa/admin-refresh/verification.json). گزارش‌های داده، سلامت سرویس‌ها، بررسی آدرس‌ها و لاگ ساخت Docker در همان پوشه قرار دارند. نمونهٔ تصاویر: [تنظیمات دسکتاپ](qa/admin-refresh/settings-desktop-chromium.png) و [رسانه‌ها در موبایل](qa/admin-refresh/media-mobile-chromium.png).

تصویر وب قبلی با نام `makan-admin-web-before:20261026` حفظ شده است. در صورت نیاز به بازگشت صرفاً رابط وب، از ریشهٔ پروژه:

```powershell
docker tag makan-admin-web-before:20261026 makan-landing-dev-web:0.10.0
docker compose --profile website up -d --wait web
```

این بازگشت به حذف داده یا اجرای Migration نیاز ندارد. ساخت دوباره از سورس فعلی، رابط جدید را برمی‌گرداند. در این نوبت Commit و Push انجام نشده‌اند؛ تغییرات برای بازبینی در پوشهٔ پروژه باقی هستند.
