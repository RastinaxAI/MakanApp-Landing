# راهنمای مدیریت محتوا — مرحله ۶

این پنل متعلق به وب‌سایت معرفی است؛ هیچ حساب یا داده آموزشی اپ اصلی ماکان را مدیریت نمی‌کند. مالک و ویرایشگر به محتوا/رسانه/FAQ دسترسی دارند؛ تنظیمات سایت مخصوص مالک است. نقش فروش به CMS دسترسی ندارد. ورود، MFA اختیاری و ساخت اولین مالک مطابق [راهنمای مدیر](admin-runbook.md) انجام می‌شود؛ حساب پیش‌فرض وجود ندارد.

## نصب و واردکردن متن موجود

Node24 و Python3.13 مطابق lockها لازم‌اند. پس از ساخت کلیدهای محلی با اسکریپت موجود:

```powershell
docker compose --profile tools build api migrate
docker compose up -d db
docker compose --profile tools run --rm migrate
docker compose up -d api
docker compose exec -T api python -m app.commands.import_content
npm run build
npm run start --workspace @makan/web
```

فرمان import تنها متن تألیف‌شده مراحل قبل، مبتنی بر PRD و تأیید مستقیم کاربر، را از `app/data/initial-marketing.json` وارد می‌کند. اجرای اول در دیتابیس فاقد CMS، ۲۶ رکورد می‌سازد؛ اجرای دوباره رکورد دارای همان kind/slug را تغییر نمی‌دهد. فرمان حساب مدیر نمی‌سازد. رویدادهای import سیستمی‌اند و actor ندارند؛ تغییرات HTTP همواره مدیر واقعی دارند. انتشار اولیه این متن، تأیید انتشار عمومی نهایی وب‌سایت یا متن حقوقی محسوب نمی‌شود: سایت هنوز noindex است.

## کار با محتوا

در `/admin/content` نوع/وضعیت/عنوان را فیلتر کنید یا پیش‌نویس جدید بسازید. صفحه اصلی، صفحه عمومی، امکان، مخاطب و FAQ فرم‌های مجزا دارند. عنوان و slug، ترتیب، نمایش عمومی، متن و SEO همان نسخه قابل تنظیم‌اند. متن اصلی خانه از فیلدهای سکشن Hero و متن اصلی سایر صفحه‌ها از تیتر/خلاصه صفحه تنظیم می‌شود. سکشن‌های صفحه اصلی و صفحات عادی، کارت‌ها، تصاویر و پیوندها قابل افزودن/حذف/جابه‌جایی‌اند. Rich Text برای متن قالب‌دار است و HTML اجرایی هنگام ذخیره در سرور حذف می‌شود.

کنترل‌های فرم تا آماده‌شدن React و هنگام درخواست فعال، غیرفعال‌اند؛ این حالت کوتاه مانع از گم‌شدن ویرایش سریع می‌شود.

«ذخیره پیش‌نویس» نسخه جدید و تغییرناپذیر می‌سازد؛ نسخه عمومی قبلی را تغییر نمی‌دهد. «پیش‌نمایش خصوصی» فقط نسخه ذخیره‌شده را نشان می‌دهد و ورود/مجوز لازم دارد. «انتشار نسخه ذخیره‌شده» آن snapshot را عمومی می‌کند. هر ویرایش بعدی همچنان خصوصی است تا دوباره منتشر شود. برای بازگرداندن محتوای عمومی قبلی، در تاریخچه پیش‌نمایش نسخه را ببینید و «انتشار این نسخه» را تأیید کنید؛ پیش‌نویس جدیدتر حفظ می‌شود.

نسخه انتخاب‌شده برای زمان‌بندی مستقل از ویرایش‌های بعدی است. تاریخ دستگاه با offset به UTC تبدیل می‌شود؛ زمان UTC سرور مرجع نمایش عمومی است. رسیدن زمان در query دیتابیس اعمال می‌شود و به بازبودن مرورگر یا اجرای job وابسته نیست. انتشار فوری، برنامه قبلی را لغو می‌کند. لغو برنامه، نسخه عمومی قبلی را حفظ می‌کند؛ «توقف انتشار» هر دو اشاره‌گر عمومی/زمان‌بندی را حذف می‌کند.

اگر مدیر دیگری تغییر داده باشد، سرور409 می‌دهد؛ صفحه را دوباره بارگذاری و تغییرات را با آخرین نسخه تطبیق دهید. داده شما روی ویرایش همکار overwrite نمی‌شود. برای محتوای منتشرشده یا زمان‌بندی‌شده، تغییر slug ممنوع است تا URL ثابت بماند. آدرس‌های زیرساخت و `home` برای صفحه عمومی جدید رزرو هستند. یک صفحه اصلی با slug `home` و یک H1 مجاز است؛ در سایر صفحات، H1 از تیتر اصلی ساخته می‌شود و سکشن hero مجزا پذیرفته نمی‌شود.

وضعیت انتشار پنل از ساعت سرور مشتق می‌شود؛ پس از رسیدن schedule، وضعیت عمومی نمایش داده می‌شود و برچسب آینده باقی نمی‌ماند.

بایگانی با تأیید صریح، نمایش عمومی و برنامه انتشار را قطع می‌کند؛ سابقه باقی می‌ماند. محتوای بایگانی‌شده در این مرحله فقط قابل خواندن/پیش‌نمایش است؛ بازیابی بایگانی یک endpoint فعال نیست. برگشت نسخه عمومی از تاریخچه برای محتوای فعال امکان‌پذیر است.

برای امکان «آماده» یا «بخشی آماده»، مرجع تأیید محصول لازم است و سرور بدون آن انتشار را رد می‌کند. این فیلد مدیریتی در API عمومی حذف می‌شود. پیام‌رسان/مدرسه/گزارش طبق تأیید پیشین آماده معرفی‌اند؛ AI همچنان نقشه راه است. مدیر باید ادعا، عدد، رضایت مشتری و تصویر واقعی را قبل انتشار بازبینی کند؛ وجود قابلیت انتشار، سند صحت ادعا نیست.

## پرسش‌ها، رسانه و تنظیمات

FAQ پاسخ ساده و پاسخ قالب‌دار دارد. دسته‌ها از `/admin/faq-categories` مدیریت می‌شوند؛ دسته دارای reference در هر نسخه قابل حذف نیست. نمایش دسته عمومی فقط با FAQ مؤثر منتشرشده انجام می‌شود. در سکشن اعتماد/FAQ می‌توان slug پرسش‌های منتخب را با ویرگول تعیین کرد؛ خالی یعنی انتخاب بر اساس ترتیب. قابلیت‌های صفحه و FAQ فقط داده منتشرشده را مصرف می‌کنند.

در `/admin/media`، JPEG/PNG/WebP/AVIF حداکثر۵MiB،۲۰میلیون پیکسل و ضلع۱۰۰۰۰پیکسل پذیرفته می‌شود. محتوای واقعی فایل decode و به WebP بدون EXIF تبدیل می‌شود؛ MIME صرفاً از پسوند پذیرفته نمی‌شود. SVG، HTML، iframe، فایل اجرایی و ویدیوی خام پذیرفته نمی‌شوند. فایل روی Volume `media_data` با نام تصادفی ذخیره و ابتدا خصوصی است؛ preview از مسیر محافظت‌شده تصویر استفاده می‌کند. انتشار نسخه استفاده‌کننده یا انتخاب صریح مالک در تنظیمات/مدیر رسانه، آن را عمومی می‌کند. تصویر scheduled قبل رسیدن زمان عمومی نیست.

تصویر عمومی را محرمانه تلقی نکنید: عمومی‌شدن برگشت‌پذیری امنیتی ندارد و توقف انتشار صفحه، نسخه‌های cache/download‌شده را پس نمی‌گیرد. فقط تصویر بدون اطلاعات شخصی و دارای مجوز منتشر کنید. فایل referenced در هر نسخه/تنظیمات قابل حذف نیست؛ تاریخچه به همین فایل وابسته است. متن جایگزین، ابعاد واقعی و `next/image` برای تصویر عمومی استفاده می‌شوند؛ تصویر خصوصی وارد optimizer عمومی نمی‌شود.

اگر حذف فایل پس از commit دیتابیس با خطای دیسک مواجه شود، orphan بدون رکورد قابل سرو ایجاد می‌شود. ابتدا اتصال/مجوز Volume را بررسی کنید. حذف دستی bulk یا پاک‌کردن Volume مجاز نیست؛ برای نگهداری، backup و فهرست UUIDهای storage را با جدول media_assets تطبیق دهید و تنها orphan تأییدشده را پس از فاصله امن و backup حذف کنید. فایل‌های دارای رکورد/نسخه را تغییر ندهید.

مالک در `/admin/settings` برند، tagline، شماره/ایمیل، URL رسمی HTTPS، لوگو و SEO پیش‌فرض را تنظیم می‌کند. لوگو بدون checkbox تأیید رسمی قابل ثبت نیست؛ تا دریافت دارایی واقعی، جایگاه مشخص حفظ می‌شود. عنوان/توضیح SEO اختصاصی صفحه بر پیش‌فرض سایت مقدم است؛ OG صفحه در صورت نبود از تنظیمات می‌آید. canonical و OG URL تنها با دامنه رسمی معتبر تولید می‌شوند. اجازه index اختصاصی صرفاً برای گیت مرحله۹ ذخیره می‌شود؛ در این تحویل robots همه صفحات noindex باقی می‌ماند. کلید سرویس، رمز و secrets در CMS جایی ندارند.

## پشتیبان و آزمون

از PostgreSQL و Volume رسانه همراه هم backup بگیرید و با همان نسخه schema بازیابی کنید. snapshot محتوا بدون فایل referenced ناقص است. در توسعه، `docker compose down` بدون `-v` داده را حفظ می‌کند؛ `down -v` داده را حذف می‌کند و برای reset عادی استفاده نشود. راهنمای عملی backup/restore و HTTPS/Compose کامل مرحله۱۰ است.

```powershell
docker compose -f compose.test.yaml --env-file .env.test up -d --wait
./scripts/test-backend.ps1
npm run lint
npm run typecheck
npm run build
./scripts/test-web-admin.ps1
apps/api/.venv/Scripts/python.exe scripts/test-cms-docker.py
```

آزمون Docker به image ساخته‌شده `makan-landing-dev-api` و DB تست مجزا روی۱۵۴۳۲ نیاز دارد؛ fixture دیتابیس، حساب و رسانه پس از آزمون حذف می‌شود. آزمون مرورگر از API۸۱۰۰ و وب۳۱۰۰ استفاده می‌کند؛ اشغال این پورت‌ها باید قبل اجرا رفع شود. داده اصلی توسعه با fixture جایگزین نمی‌شود. `-CmsOnly -FailFast` برای بررسی محدود CMS است و جای آزمون کامل را نمی‌گیرد.

مقاله/آموزش/آپارات/مجموعه در مرحله۷، فرم واقعی/CRM در مرحله۸ و SEO/عملکرد/استقرار نهایی در مراحل۹–۱۰ هستند. این راهنما وجود آن‌ها را ادعا نمی‌کند.
