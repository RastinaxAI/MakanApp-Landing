# بازطراحی پیشخوان و ورود پیامکی — ۱۴ اکتبر ۲۰۲۶

درخواست مالک: ورود فقط با شماره همراه و OTP، دیباگ111111، اتصال ملی‌پیامک از تنظیمات، پیشخوان مرتب با ساختار مشابه وردپرس، Tailwind و نشان/فاوآیکون مربع با گوشه گرد. کد شش‌رقمی و شماره مالک با پاسخ مستقیم مالک تأیید شدند؛ شماره شخصی در این گزارش یا سورس ثبت نمی‌شود.

## تغییرات

- فرم ورود شماره همراه و مرحله کد؛ پیام خطای فارسی، تبدیل رقم فارسی، شمارش ارسال دوباره، MFA اختیاری پس از OTP.
- شماره‌های ثبت‌شده و فعال مدیران تنها اجازه ورود دارند؛ درخواست کد حساب خودکار نمی‌سازد.
- migration افزایشی0008_phone_otp: شماره یکتا و نرمال، email/password قدیمی nullable و محفوظ، admin_otps و sms_configuration. هیچ جدول قبلی بازسازی یا حذف نمی‌شود.
- OTP با HMAC و اتصال به challenge/session، انقضای۵دقیقه، حداکثر۵تلاش، فاصله ارسال۶۰ثانیه و quota مشترک PostgreSQL. کد هر مرحله فقط یک‌بار مصرف می‌شود. کد توسعه برچسب دارد و با خاموش‌شدن دیباگ دیگر معتبر نیست.
- دیباگ فقط development/test؛ compose تولید آن را false می‌گذارد. خطای provider به دیباگ fallback ندارد. ورود با ایمیل/رمز در محیط واقعی پاسخ410 دارد. تنها fixtureهای regression در APP_ENV=test می‌توانند legacy را صریح فعال کنند؛ قابلیت محیط تولید نیست.
- تنظیمات پیامک تنها مالک؛ رمزگذاری نام کاربری و رمز وب‌سرویس با کلید موجودAUTH_MFA_KEY و AAD مستقل، If-Match و audit بدون credential. API عمومی تنظیمات این داده را برنمی‌گرداند. تغییر حساس نیازمند OTP جدید همان نشست و در صورت فعال‌بودن، MFA است.
- اتصال REST با HTTPS ثابت، timeout۸ثانیه، منع redirect و پاسخ محدود۱۶KiB. روش BaseServiceNumber با username/password/text/to/bodyId مطابق [سورس رسمی ملی‌پیامک](https://github.com/Melipayamak/melipayamak-python/blob/master/melipayamak/sms/rest.py). الگوی یک‌پارامتری باید توسط provider تأیید شود؛ داده الگو یا مشخصات پنل حدس زده نمی‌شود.
- بررسی اتصال با GetCredit پیامک نمی‌فرستد. API تولید شبکه خروجی جدا برای تماسHTTPS دارد؛ DB و وب همچنان پورت عمومی ندارند.
- برای bootstrap تولید، CLI خصوصی sms configure وجود دارد؛ reset-debug در production/staging رد می‌شود. restore نشست، challenge و OTP بازیابی‌شده را باطل و cleanup کدهای منقضی را حذف می‌کند.
- Tailwind: نوار بالایی، سایدبار ثابت سمت راست با گروه‌بندی، drawer موبایل، فعال‌بودن درست زیرمنو، دسترسی سریع، جدول مدیران و فرم‌های تراز. داده KPI واقعی است و نمودار فرضی اضافه نشده است.
- تصویر PNG لوگو دست‌نخورده؛ radius نمایش۱۲px به‌جای radius دایره‌ای. فاوآیکون SVG با نسخه بهینه۱۲۸px همان تصویر و clip گوشه‌های گرد، بدون طراحی نشان تازه؛ ابزار بازتولید scripts/build-brand-icon.mjs، حجم۱۹۸۷بایت. PNG اصلی و hash آن حفظ شدند.

## محدودیت اتصال پیامک

مشخصات واقعی ملی‌پیامک و الگوی تأییدشده ارائه نشده‌اند. تست قرارداد ارسال با HTTPX MockTransport فقط در تست و روی PostgreSQL واقعی انجام می‌شود؛ runtime از سرویس واقعی استفاده می‌کند. ارسال پیامک واقعی یا دریافت روی موبایل ادعا نمی‌شود. مانور HTTPS نیز تحویل OTP کنترل‌شده در fixture خصوصی دارد؛ مسیر وبی تزریق یا کد ثابت در staging ندارد.

## بررسی‌ها

۲۰۹ تست Pytest روی PostgreSQL واقعی موفق شدند. Build تولید Node24، ESLint، TypeScript، Ruff و actionlint موفق‌اند. ۱۲ تست فرم و پنل در Chromium/Edge، Firefox و WebKit موفق؛ ۱۲ ارزیابی خودکار Axe با صفر violation، عرض‌های۳۹۰/۷۶۸/۱۴۴۰ و بررسی تراز، صفحه‌کلید و منوی موبایل. این نتیجه ممیزی کامل انسانی WCAG نیست. هر پنج image API/migrate/DB/Caddy/web ساخته شدند. هر۷گیت پذیرش Docker/HTTPS/CRM/CSRF/RBAC/backup/restore/بقای داده و readiness موفق شدند؛ head پشتیبان0008 بود و نشست‌های قدیمی پس از restore باطل شدند. ۲۴تست مرورگر HTTPS در سه موتور موفق؛ صفحه ورود تولید بدون ایمیل/رمز/کد توسعه، فاوآیکون بهینه در هر سه موتور، cookie امن، CSP nonce و hydration بررسی شدند. تحویل OTP این تست، fixture کنترل‌شده خصوصی است و ارسال پیامک واقعی نیست. اسکن pip-audit وابستگی runtime نیز بدون آسیب‌پذیری شناخته‌شده بود. پس از این مجموعه، رنگ icon بستن drawer تیره اصلاح شد؛ ۳بازآزمایی اختصاصی کنتراست عادی/hover حداقل۳، بازگشت focus با Escape، منوی موبایل و فرم پیامک در هر سه موتور موفق شدند. Build نهایی Docker وب پس از این اصلاح موفق شد؛ گیت HTTPS۲۴تایی پیش از این تغییر محدود رنگ اجرا شده بود و API/schema تغییری نکردند. امتیاز Lighthouse جدید یا اسکن جدید تمامی imageها ادعا نمی‌شود. شواهد این تغییر در docs/qa/admin-refresh هستند. اجرای نخست قبل از روشن‌بودن PostgreSQL تست ناموفق بود؛ diagnostic خصوصی پاکسازی و رمز admin فقط DB تست rotate شد. دیتابیس اصلی و کلیدهای آن تغییر نکردند. دو تست legacy نیز برای قرارداد جدید و مدل تاریخی migration اصلاح شدند؛ اجراهای ناموفق موفق شمرده نمی‌شوند.

تست مرورگر مسیرهای OTP/SMS جاافتاده در allowlist پراکسی را کشف کرد؛ اصلاح و بازآزمایی شدند. WebKit مسابقه پاک‌شدن ورودی تأیید پس از پاسخ ارسال را کشف کرد؛ ورودی تا پایان ارسال بسته و هر۱۲تست دوباره موفق شدند. یک assertion نیز به فرم محدود شد تا با route announcer داخلی Next تداخل نداشته باشد. دستور build یک بار در ریشه اشتباه اجرا شد و از apps/web موفق شد؛ گزینه نامعتبر --no-build برای compose run حذف شد. تست اشغال‌بودن پورت ابتدا اجرا نشد؛ تنها وب همین پروژه برای اجرای fixture متوقف شد.

## نسخه محلی

قبل از migration بکاپ خصوصی گرفته شد. حساب مالک موجود با CLI خصوصی به شماره تأییدشده مالک متصل شد؛ حساب تازه یا داده آموزشی/درخواست فرضی ساخته نشد. head جدید0008، مدیر۱، صفحه۲۶، نسخه۲۹ و درخواست۰؛ این چهار شمار با baseline برابرند. ورود واقعی شماره مالک از فرم مرورگر، نمایش تنظیمات پیامک و خروج با صفر خطای browser موفق شدند. credential واقعی پیامک هنوز ثبت نشده؛ توسعه111111 فعال است. سایت Docker روی127.0.0.1:3100 روشن است. شماره شخصی، cookie و تصویر پنل واقعی فقط در مسیر خصوصی .preview نگهداری می‌شوند.

## استفاده

[README](../README.md) دستورهای ساده ورود، ساخت مالک، اتصال ملی‌پیامک و بازیابی محلی را دارد. حساب‌های قبلی با bind-phone بدون حذف داده متصل می‌شوند. شماره مالک فقط در ورودی خصوصی CLI و دیتابیس ذخیره می‌شود. Push مجاز نیست.

فهرست فایل‌ها در [changed-files](qa/admin-refresh/changed-files.md) است. تغییر قبلی کاربر در apps/web/next-env.d.ts از commit کنار گذاشته می‌شود.

تست کنتراست در بررسی TypeScript به default برای اندیس‌های RGB نیاز داشت؛ اصلاح شد، typecheck و lint فایل‌های تغییرکرده موفق شدند و context قدیمی Docker که تست اصلاح‌نشده داشت ناموفق ماند. ساخت تازه با فایل اصلاح‌شده موفق است. اسکن شناخته‌شده۴۲credential/شماره شخصی در۲۶۶۳فایل Git-visible و diff-check موفق شدند؛ داده خصوصی در فایل‌های قابل ثبت پیدا نشد. تصویر وب نهایی روی سرویس محلی فعال شد و ورود/خروج مالک از فرم واقعی دوباره با صفر خطای مرورگر موفق شد.
