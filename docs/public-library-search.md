# اصلاح عنوان صفحات و جست‌وجوی آموزش و وبلاگ

تاریخ: ۲۶ اکتبر ۲۰۲۶

## تغییرات

- عنوان، مسیر صفحه و توضیح معرفی در `/learn`، `/blog` و `/solutions` وسط‌چین شدند و فاصلهٔ متعادل گرفتند.
- جست‌وجوی آموزش و وبلاگ همیشه در صفحه دیده می‌شود؛ دکمهٔ «فیلترها» پنجرهٔ تنظیمات را باز می‌کند.
- مخاطب، موضوع، سطح، دسته‌بندی، برچسب، مرتب‌سازی و نوع محتوای آموزشی از همان APIهای قبلی استفاده می‌کنند.
- تعداد فیلترهای فعال نمایش داده می‌شود و هر فیلتر جداگانه قابل حذف است.
- جست‌وجوی جدید فیلترهای اعمال‌شده را حفظ می‌کند و صفحه‌بندی از ابتدا شروع می‌شود. آدرس نتیجه قابل اشتراک است.
- «انصراف» و Escape تغییرات اعمال‌نشده را کنار می‌گذارند. فوکوس به دکمهٔ فیلتر برمی‌گردد.
- در موبایل، محتوای بلند پنجره اسکرول می‌شود و اقدامات پایین پنجره در دسترس می‌مانند.

هدرهای استاندارد و عنوان/توضیح ساخته‌شده با ویجت‌های Heading و RichText صفحه‌ساز هر دو پوشش داده می‌شوند. جای خود متن با DOM Range و تراز محاسبه‌شده بررسی می‌شود؛ قرار داشتن کادر تمام‌عرض عنوان در مرکز، به‌تنهایی معیار پذیرش نیست.

## حفظ قابلیت‌ها و داده‌ها

محتوای عنوان‌ها همچنان از CMS دریافت می‌شود. لینک‌ها، مدل‌ها، APIها و مهاجرت‌های دیتابیس تغییر نکرده‌اند. هیچ محتوای آزمایشی در دیتابیس اصلی ایجاد نمی‌شود؛ آزمون‌های انتشار و جست‌وجو از دیتابیس موقت جداگانه استفاده می‌کنند.

## فایل‌های مربوط به این تغییر

- `apps/web/src/features/learning/library-search.tsx`: جست‌وجو و پنجرهٔ فیلتر مشترک.
- `apps/web/src/features/learning/public.tsx`: اتصال رابط جدید به داده‌ها و قرارداد موجود.
- `apps/web/src/features/cms/public-page.tsx`: تعیین محدودهٔ چیدمان عنوان راهکارها.
- `apps/web/src/styles/public-polish.css`: چیدمان عنوان و استایل واکنش‌گرای جست‌وجو و فیلتر.
- `apps/web/tests/v2/public-library-search.spec.ts`: تست عملکرد واقعی و نمایش سه اندازه و سه موتور مرورگر.
- `scripts/run-v2-quality.py`: اضافه‌شدن نام مرحله و مجموعهٔ آزمون جدید.
- `scripts/check-library-runtime.cjs`: بررسی فقط‌خواندنی رابط نسخهٔ مستقر.

### محدودیت محیط محلی

در نخستین بررسی پس از Build سنگین Docker، SSR با Timeout ارتباط وب و API پاسخ ۵۰۰ داد. راه‌اندازی مجدد همان سرویس‌های API و وب با تنظیمات یکسان انجام شد؛ داده‌ها، Timeoutهای برنامه و کد Backend تغییر نکردند. علت ریشه‌ای کندی مقطعی محیط محلی در این تغییر حل نشده است. گزارش تلاش ناموفق در `attempt-runtime-before-restart.log` و لاگ‌های `runtime-timeout-*.log` حفظ شده‌اند. پس از ساخت نهایی نیز API برای آماده‌سازی محیط دوباره راه‌اندازی شد. راه‌اندازی مجدد، رفع ریشه‌ای این مسئله محسوب نمی‌شود.

گزارش‌های ماشینی و اسکرین‌شات‌ها در `docs/qa/public-library-search` قرار دارند.

دستورهای آزمون از ریشهٔ پروژه:

```powershell
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py build --phase public-library-search
docker compose --env-file .env.test -f compose.test.yaml up -d --wait
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase public-library-search --spec public-library-search --project all
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase public-library-search --suite legacy --spec learning --project chromium
# بررسی فقط‌خواندنی نسخهٔ محلی مستقر:
node scripts/check-library-runtime.cjs
```
