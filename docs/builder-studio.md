# بازطراحی بوم ویرایش ماکان

## خواسته و محدوده

رابط صفحه‌ساز از نو با محوریت بوم درگ‌ودراپ طراحی شد. فرم‌های مشخصات برگه، SEO، انتشار و ابزارهای کتابخانه از بالای صفحه حذف و به پنل کناری منتقل شدند. موتور ویرایش، سند نسخهٔ ۲، APIهای CMS، تاریخچه، رسانه، احراز هویت و CRM موجود حفظ شده‌اند؛ صفحه‌ساز یا پایگاه دادهٔ دوم ساخته نشده است.

«هوشمند» در این تغییر به رفتار وابسته به انتخاب اشاره دارد: انتخاب عنصر، تب داخلی یا والد، تنظیمات همان بخش را نشان می‌دهد. سرویس هوش مصنوعی مولد یا اتصال به مدل خارجی اضافه نشده است.

## تجربه استفاده

- برگه‌های غیر FAQ مستقیماً در بوم تمام‌صفحه باز می‌شوند؛ مسیر اطلاعات مرجع با `?mode=metadata` همچنان در دسترس است.
- کتابخانهٔ قابل جست‌وجو، عناصر را در گروه‌های چیدمان، پایه و بازاریابی نشان می‌دهد. افزودن و جابه‌جایی روی بوم و کانتینرها با کشیدن انجام می‌شود.
- انتخاب عنصر، پنل محتوا، استایل و پیشرفته را باز می‌کند. برای تب‌ها، انتخاب روی بوم به همان تب و متن و تصویر مستقل آن می‌رسد.
- ویرایشگر متن در بوم فقط خود متن را نشان می‌دهد؛ نوار ابزار، انتخاب عکس و پیوند در تنظیمات کنار صفحه قرار دارند.
- مسیر انتخاب در بالای بوم، دسترسی مستقیم به کانتینر والد را می‌دهد. لایه‌ها، تکثیر، حذف، واگرد و انجام دوباره حفظ شده‌اند.
- پیش‌نمایش دستگاه عرض واقعی ۱۴۴۰، ۷۶۸ یا ۳۹۰ پیکسل دارد و برای جاگرفتن در فضای طراحی مقیاس می‌شود. عرض iframe با کوچک‌نمایی ظاهری عوض نمی‌شود.
- پنل قابل جمع‌شدن است. در صفحهٔ باریک، بوم بالا و پنل پایین آن قرار می‌گیرند تا عناصر و محل رهاکردن هم‌زمان در دسترس باشند.
- فرم دمو و تماس در بوم از همان کامپوننت خروجی عمومی استفاده می‌کنند؛ در حالت طراحی دریافت توکن و ارسال فرم غیرفعال است.
- ذخیره دستی و میان‌بر `Ctrl+S` یا `Cmd+S`، ذخیره خودکار موجود، پیش‌نمایش خصوصی و انتشار واقعی حفظ شده‌اند. میان‌بر ذخیره، ابتدا متن در حال ویرایش را از حالت تمرکز خارج می‌کند تا آخرین متن نیز ثبت شود.

## معماری

`studio.tsx` پوستهٔ تازه را با Composition رسمی Puck و اجزای Drawer، Fields، Outline و Preview می‌سازد؛ Layout آماده قبلی استفاده نمی‌شود. `editor.tsx` مسئول بارگیری سند، کنترل نسخه، ذخیره، انتشار و تنظیمات باقی مانده است. کنترل‌های محتوایی و استایل همان رجیستری و اعتبارسنجی قبلی را استفاده می‌کنند.

در تب‌های تو‌در‌تو، تغییر مقدار Radix در رویداد pointer-down ممکن بود با انتخاب کانتینر تداخل کند؛ انتخاب تب در رویداد click نیز اعمال می‌شود. ثبت ناحیه تعاملی تب‌ها به خود عنصر محدود است تا والد، تب‌های فرزند را ثبت نکند.

تیترهای قابل ویرایش، متن را در رویداد `input` و پایان ترکیب نویسه ثبت می‌کنند. در حالت طراحی، React فرزند متنی ناحیهٔ `contentEditable` را بازنویسی نمی‌کند؛ همگام‌سازی تغییرات پنل و تاریخچه زمانی انجام می‌شود که کاربر داخل آن تیتر تایپ نمی‌کند. این کار از پاک‌شدن متن در WebKit و جابه‌جایی مکان‌نما هنگام تایپ جلوگیری می‌کند. خروجی عمومی همچنان تیتر متنی عادی و قابل ایندکس است.

هیچ وابستگی، API، جدول، Migration یا تغییر قراردادی به سند محتوا اضافه نشده است. ارسال عمومی فرم همان API موجود و ثبت واقعی در CRM را استفاده می‌کند. تغییرات این مرحله شامل حساب‌های مدیر یا Backend اصلی ماکان نیست.

مرجع فنی: [Composition در Puck](https://puckeditor.com/docs/extending-puck/composition).

## بررسی قابل تکرار

```powershell
npm run lint
npm run typecheck
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py build --phase builder-studio
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase builder-studio --spec studio --project chromium
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase builder-studio --spec all --project all
```

آزمون‌ها از PostgreSQL و داده‌های مستقل آزمایشی استفاده می‌کنند و دادهٔ آزمایشی به دیتابیس اصلی وارد نمی‌کنند. نتایج این مرحله در `docs/qa/builder-studio` نگهداری می‌شوند؛ گزارش‌های تحویل قبلی بازنویسی نمی‌شوند.

## نتیجه نهایی در ۲۵ اکتبر ۲۰۲۶

- Build Production، بررسی TypeScript و ESLint موفق شدند.
- ۳۰ آزمون مرورگر، شامل ۱۰ سناریو در هر یک از Chromium، Firefox و WebKit، بدون شکست، skip یا flaky موفق شدند. تایپ حرف‌به‌حرف، ثبت آخرین متن با میان‌بر، تصویر تب‌ها، ذخیره و انتشار، بازیابی، قالب‌ها، سربرگ، فرم واقعی دمو و CRM، نمایش ۲۷ عنصر و رگرسیون صفحات عمومی در این مجموعه هستند.
- image لینوکسی وب با Docker ساخته و روی `http://127.0.0.1:3100` اجرا شد. هر چهار سرویس وب، API، PostgreSQL و نگهداری سالم‌اند؛ حضور کد پوستهٔ جدید در فایل اجرایی سرویس وب نیز بررسی شد.
- هفت مسیر اجرای محلی، شامل صفحات اصلی، ورود، readiness، رد دسترسی مهمان به API مدیریت و پاسخ ۴۰۴، موفق بررسی شدند.
- شمار و checksum ردیف‌های اصلی در `pages`، `page_revisions`، `media_assets` و `leads` قبل و بعد دقیقاً برابر بود: ۲۶ برگه و ۵۰ نسخهٔ موجود حفظ شدند. Alembic همچنان `0009_demo_crm` است؛ Migration تازه‌ای اجرا نشد.
- نسخه قبلی image وب با نام `makan-builder-web-before:20261025` نگهداری شد. Volumeها حذف یا بازسازی نشدند و Backend اصلی ماکان تغییر نکرد.

شواهد: `docs/qa/builder-studio/verification.json`، گزارش کامل `browser.json`، تصاویر دسکتاپ و موبایل هر سه مرورگر، لاگ ساخت Docker، گزارش سلامت سرویس‌ها، `local-runtime.json` و مقایسه‌های دیتابیس. بررسی مرورگر روی خروجی Production انجام شد؛ اجرای اولیه در حالت توسعه با بازبارگذاری مکرر صفحه ورود همراه بود و مبنای تحویل نیست.
