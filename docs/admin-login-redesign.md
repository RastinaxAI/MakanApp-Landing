# بازطراحی صفحهٔ ورود مدیریت

## تغییرات

- صفحهٔ ورود در دسکتاپ دو بخش دارد: معرفی پیشخوان با آبی برند و فرم ورود روی زمینهٔ سفید.
- در موبایل و تبلت، فرم به‌صورت تک‌ستونه نمایش داده می‌شود؛ عنوان، ورودی‌ها، دکمه‌ها و فضای خالی متناسب با اندازهٔ صفحه‌اند.
- لوگوی اصلی حفظ شده و قاب آن مربع با گوشه‌های گرد است.
- دو مرحلهٔ شماره همراه و تأیید کد مشخص‌اند. شماره پس از درخواست کد فقط‌خواندنی است و دکمهٔ تغییر شماره همچنان در دسترس است.
- پیام توسعه و کد `111111` حفظ شده‌اند و فقط با تنظیم `debug` دریافتی از API نمایش داده می‌شوند.
- ورود OTP، خطای کد اشتباه، اعتبارسنجی شماره، نرمال‌سازی ارقام فارسی، ارسال مجدد، MFA اختیاری و تغییر مسیر بعد از ورود حفظ شده‌اند.
- فوکوس پس از پاسخ درخواست کد روی ورودی کد قرار می‌گیرد؛ در صورت نیاز به MFA، ورودی عامل دوم فوکوس می‌گیرد. ارسال مجدد در زمان درخواست در حال اجرا غیرفعال است.
- استایل‌ها به `.admin-login` محدودند و صفحهٔ خطای مدیریت، صفحات عمومی و سایر بخش‌های پیشخوان را تغییر نمی‌دهند.

## اعتبارسنجی

- Build تولید Next.js و TypeScript: موفق.
- ESLint 10 کل پروژهٔ وب: بدون خطا یا هشدار.
- ۱۵ تست رابط و ورود واقعی روی Chromium، Firefox و WebKit: موفق؛ نمایش ۳۲۰، ۷۶۸ و ۱۴۴۰ پیکسل، اعتبارسنجی، ارقام فارسی، فوکوس، کد اشتباه، تغییر شماره، ورود موفق و تغییر مسیر حساب واردشده.
- ۴ تست رگرسیون OTP و دسترسی‌ها روی Chromium: موفق؛ شمارهٔ ناشناخته دسترسی نمی‌گیرد و مجوز تنظیمات پیامک همچنان کنترل می‌شود.
- مجموع: ۱۹ تست موفق؛ بدون شکست، Skip یا Flaky در اجرای نهایی.
- بررسی دسترس‌پذیری axe در سه اندازه و حالت خطای کد: موفق. کنتراست متن بخش آبی در اولین بررسی اصلاح شد؛ گزارش تلاش اولیه حفظ شده است.
- Build چندمرحله‌ای Docker و استقرار محلی: موفق. Build ID فعال: `b9dLN82pRDCWoTSkb4EDN`.
- ۹ بررسی رابط روی نسخهٔ مستقر و ۳ بررسی رگرسیون صفحات عمومی: موفق. بررسی اصلی فقط‌خواندنی بود و هیچ OTP یا ورود واقعی در دیتابیس اصلی ایجاد نشد.
- تطبیق شمارش و Checksum ده جدول اصلی: بدون تغییر؛ ۲۶ برگه و ۵۰ نسخهٔ محتوا حفظ شده‌اند.
- چهار سرویس موجود در پایان بررسی سالم‌اند.
- API و Migration جدیدی وجود ندارد. شماره‌ها، تنظیمات پیامک و حساب‌ها تغییر نکرده‌اند.
- ارسال پیامک واقعی و Lighthouse در این تغییر دوباره آزموده نشده‌اند.
 مستندات ماشینی و تصاویر در `docs/qa/admin-login` قرار دارند.

```powershell
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py build --phase admin-login
docker compose --env-file .env.test -f compose.test.yaml up -d --wait
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase admin-login --spec admin-login --project all
apps/api/.venv/Scripts/python.exe -X utf8 scripts/run-v2-quality.py browser --phase admin-login --suite legacy-otp --spec otp-admin --project chromium
```

تست ورود روی دیتابیس موقت مستقل اجرا می‌شود؛ در بررسی نسخهٔ اصلی هیچ شماره‌ای ارسال و هیچ ورود یا تنظیم امنیتی تغییر داده نمی‌شود.

## داده‌ها و استقرار

این تغییر API، قرارداد احراز هویت یا Migration جدید ندارد. تنظیمات پیامک و حساب‌های مدیران حفظ می‌شوند. تصویر قبلی وب با برچسب `makan-login-before:20261026` نگهداری شده است. به‌دلیل وجود تغییرات قبلی در Workspace، Commit جدید انجام نمی‌شود و Push نیز مجوز ندارد.


## محدودیت محیط محلی

در نخستین بررسی پس از Build، صفحهٔ ورود در سه اندازهٔ Chromium قابل استفاده بود؛ بررسی صفحات عمومی با خطای ۵۰۰ متوقف شد. API و وب با همان تنظیمات راه‌اندازی مجدد شدند. این اقدام مشکل کندی مقطعی API را ریشه‌یابی یا رفع دائمی نمی‌کند؛ کد Backend و Timeoutهای برنامه تغییر نکرده‌اند. گزارش تلاش اول و لاگ‌های سرویس در `docs/qa/admin-login/attempt-runtime-before-api-restart.log` و فایل‌های `runtime-timeout-*.log` حفظ شده‌اند.
