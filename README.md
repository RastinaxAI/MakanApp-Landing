# ماکان — راهنمای اجرای سایت و پنل مدیریت

سایت معرفی ماکان و پنل مدیریت مستقل آن؛ شامل مدیریت محتوا، مقاله، ویدیوهای آپارات و درخواست‌های دمو و مشاوره.

**مسیر کار:** اجرای برنامه‌ها ← بازکردن سایت ← ورود مدیر با شماره همراه ← مدیریت محتوا و درخواست‌ها.

## اجرای سریع همین نسخهٔ آماده

روی این کامپیوتر، برنامه‌ها ساخته شده‌اند و حساب مالک به شمارهٔ همراه تأییدشده متصل است. برای استفاده، نصب اولیه یا ساخت دوبارهٔ مدیر لازم نیست.

۱. **Docker Desktop** را باز کنید و صبر کنید تا آماده شود.

۲. **PowerShell 7** را باز کنید و این دستورها را اجرا کنید:

```powershell
cd C:\Users\OmidrezaBagheriyan\Desktop\MakanWebsite
docker compose --profile website up -d --wait db api web
```

۳. این آدرس‌ها را باز کنید:

| بخش | آدرس |
| --- | --- |
| سایت | http://127.0.0.1:3100 |
| ورود پنل مدیریت | http://127.0.0.1:3100/admin/login |
| بررسی سلامت برنامه‌ها | http://127.0.0.1:3100/health/ready |

۴. در صفحهٔ ورود، شمارهٔ مدیر ثبت‌شده را وارد کنید، **«دریافت کد ورود»** را بزنید و در حالت توسعه، کد **111111** را وارد کنید.

ورود با ایمیل و رمز جایگزین شده است. در حالت توسعه پیامکی ارسال نمی‌شود؛ شماره‌ای که به حساب مدیر فعال متصل نیست، اجازهٔ ورود ندارد. اگر MFA را فعال کرده‌اید، کد برنامهٔ تأییدکننده یا کد بازیابی هم لازم است.

## نصب اولیه روی سیستم جدید

این بخش برای نصب تازه است. اگر نسخهٔ فعلی را اجرا می‌کنید، از بخش بالا استفاده کنید.

**پیش‌نیاز:** Docker Desktop در حالت Linux containers و PowerShell 7. برای اجرای Docker، نصب جداگانهٔ Node، Python و PostgreSQL لازم نیست. ساخت اولیه به اینترنت نیاز دارد و ممکن است چند دقیقه طول بکشد.

PowerShell را در پوشهٔ پروژه باز کنید. دستورها را به‌ترتیب اجرا کنید؛ اگر یک دستور خطا داد، پیش از دستور بعدی آن خطا را رفع کنید.

### ۱. ساخت تنظیمات خصوصی

```powershell
pwsh -NoProfile -File .\scripts\setup-development.ps1
```

این دستور فایل‌های خصوصی `.env` و `.env.test` و کلیدهای لازم را آماده می‌کند؛ مقدارهای موجود را حفظ می‌کند. این فایل‌ها را داخل Git یا پیام عمومی قرار ندهید.

### ۲. ساخت برنامه‌ها

```powershell
docker compose --parallel 1 --profile tools --profile website build api migrate web
```

ساخت‌ها پشت سر هم انجام می‌شوند تا مصرف حافظه کمتر باشد.

### ۳. آماده‌کردن دیتابیس و اجرای Backend

```powershell
docker compose up -d --wait db
docker compose --profile tools run --rm migrate
docker compose up -d --wait api
```

`migrate` ساختار دیتابیس را با Alembic آماده یا به‌روز می‌کند. آن را قبل از اجرای نسخهٔ جدید برنامه انجام دهید.

### ۴. واردکردن محتوای اولیهٔ سایت

```powershell
docker compose exec -T api python -m app.commands.import_content
docker compose exec -T api python -m app.commands.refresh_learning_intro
docker compose exec -T api python -m app.commands.refresh_form_copy
docker compose exec -T db psql -U postgres -d makan_landing -c ANALYZE
```

این دستورها متن‌های اولیه را آماده می‌کنند و ویرایش‌های قبلی مدیر را حفظ می‌کنند. مقاله، ویدیو و درخواست مشتری فرضی اضافه نمی‌شود؛ آموزش‌ها را خودتان از پنل ایجاد و منتشر کنید.

### ۵. اجرای سایت و ساخت اولین مالک

```powershell
docker compose --profile website up -d --wait web
docker compose exec -it api python -m app.commands.admin bootstrap
```

در پاسخ به `Administrator phone`، شمارهٔ همراه مدیر اصلی را وارد کنید. سپس [صفحهٔ ورود پنل](http://127.0.0.1:3100/admin/login) را باز کنید و با همان شماره و کد توسعهٔ **111111** وارد شوید.

`bootstrap` فقط برای نصب تازه و فهرست خالی مدیران است. اگر پیام `An owner already exists` دیدید، حساب موجود را استفاده کنید؛ ساخت مالک را تکرار نکنید. مدیران بعدی را از **پیشخوان ← حساب‌های مدیران** اضافه کنید.

اگر حساب قدیمی با ایمیل دارید ولی شماره به آن متصل نیست:

```powershell
$managerEmail = Read-Host 'ایمیل حساب قدیمی'
docker compose exec -it api python -m app.commands.admin bind-phone --email $managerEmail
```

شمارهٔ همراه را در مرحلهٔ بعد وارد کنید. همان حساب حفظ می‌شود و نشست‌های قبلی آن بسته می‌شوند.

## اتصال ملی‌پیامک و فعال‌کردن ارسال واقعی

در پنل وارد **تنظیمات ← پنل پیامکی** شوید:

1. نام کاربری ملی‌پیامک، **رمز وب‌سرویس** و **شناسهٔ الگوی خدماتی تأییدشده (Body ID)** را وارد کنید. الگو باید یک پارامتر برای کد ورود شش‌رقمی داشته باشد.
2. «اتصال پنل پیامکی فعال باشد» را انتخاب کنید. فعلاً حالت توسعه را روشن نگه دارید.
3. «دریافت کد تأیید تغییرات» را بزنید، کد توسعهٔ **111111** را وارد و تنظیمات را ذخیره کنید.
4. «بررسی اتصال» را بزنید. این بررسی پیامکی ارسال نمی‌کند؛ ارتباط و مشخصات ورود پنل را بررسی می‌کند.
5. برای فعال‌کردن ارسال واقعی، یک کد تأیید **جدید** دریافت کنید، حالت توسعه را خاموش و تنظیمات را ذخیره کنید. بین درخواست دوبارهٔ کد حداقل **۶۰ ثانیه** فاصله لازم است.
6. خارج شوید و دوباره وارد شوید؛ این بار باید کد تصادفی شش‌رقمی را از پیامک دریافت کنید.

اطلاعات پنل رمزگذاری می‌شوند و دوباره نمایش داده نمی‌شوند. کد تأیید هر تغییر فقط یک بار قابل استفاده است. خطای سرویس پیامکی باعث فعال‌شدن خودکار کد ثابت نمی‌شود. ارسال واقعی با حساب شما پس از ثبت مشخصات و الگوی معتبر قابل آزمایش است.

اگر تنظیم اشتباه پیامک، ورود **محلی** را قطع کرد، حالت توسعه را برگردانید:

```powershell
docker compose exec -it api python -m app.commands.sms reset-debug
```

این دستور در محیط Production و staging مجاز نیست و MFA فعال را حذف نمی‌کند.

## اجرای دوباره، توقف و به‌روزرسانی

**روشن‌کردن سایت پس از خاموش‌شدن کامپیوتر:**

```powershell
docker compose --profile website up -d --wait db api web
```

**توقف برنامه‌ها:**

```powershell
docker compose --profile website stop web api db
```

داده‌ها و تصاویر پس از توقف باقی می‌مانند. از `down --volumes` برای این محیط استفاده نکنید؛ داده‌های ذخیره‌شده را حذف می‌کند.

**پس از دریافت نسخهٔ جدید کد:** ابتدا از داده‌های مهم پشتیبان بگیرید، سپس:

```powershell
docker compose --profile website stop web api
docker compose --parallel 1 --profile tools --profile website build api migrate web
docker compose up -d --wait db
docker compose --profile tools run --rm migrate
docker compose --profile website up -d --wait api web
```

برای به‌روزرسانی معمول، ساخت مالک و ورود دوبارهٔ محتوای اولیه لازم نیست. دستورهای نصب تازه را برای حذف یا بازسازی دیتابیس موجود استفاده نکنید.

## اگر سایت باز نشد

```powershell
# وضعیت برنامه‌ها؛ سرویس‌ها باید running و healthy باشند
docker compose --profile website ps

# خطاهای اخیر
docker compose --profile website logs --tail 60 web api
```

| مشکل | کار لازم |
| --- | --- |
| Docker در دسترس نیست | Docker Desktop را باز کنید و تا آماده‌شدن آن صبر کنید. |
| خطای تنظیمات یا متغیر محیطی | `setup-development.ps1` را اجرا کنید؛ فایل `.env` موجود را حفظ کنید. |
| پورت۳۱۰۰ اشغال است | اجرای دیگر همین سایت روی۳۱۰۰ را متوقف کنید و دوباره تلاش کنید. |
| Backend آماده نیست یا سلامت۵۰۳ است | وضعیت DB/API و خروجی `migrate` را بررسی کنید؛ لاگ‌ها را بخوانید. |
| شماره اجازهٔ ورود ندارد | شماره باید برای حساب مدیر فعال ثبت شده باشد؛ بخش ساخت یا اتصال مدیر را ببینید. |
| کد نادرست یا منقضی است | کد جدید دریافت کنید؛ فاصلهٔ ارسال و شمارش صفحه را رعایت کنید. |
| پیامک نمی‌رسد | تنظیمات پنل، رمز وب‌سرویس و الگوی تأییدشده را بررسی کنید؛ برای بازیابی محلی از `reset-debug` استفاده کنید. |
| صفحهٔ اصلی محتوای اولیه ندارد | بخش «واردکردن محتوای اولیهٔ سایت» را بررسی کنید. |

فایل `.env` را برای رفع خطا حذف نکنید؛ ساخت رمز تازه، رمز ذخیره‌شدهٔ دیتابیس موجود را عوض نمی‌کند.

## انتشار روی دامنهٔ واقعی

دستورهای بالا برای اجرای محلی هستند. برای سرور و HTTPS از [راهنمای استقرار](docs/production-runbook.md) و [راهنمای پشتیبان‌گیری و بازیابی](docs/backup-restore-runbook.md) استفاده کنید. دامنه و سرور عمومی هنوز مشخص نشده‌اند.

در محیط انتشار، کد ثابت **111111** غیرفعال است. قبل از اولین ورود مدیر، اپراتور با فایل تنظیمات همان محیط، اتصال پیامکی را آماده می‌کند؛ نمونهٔ مسیر مطابق راهنمای استقرار:

```bash
docker compose -f compose.production.yaml --env-file /etc/makan-landing/production.env exec -it api python -m app.commands.sms configure
```

این دستور مشخصات ملی‌پیامک را به‌صورت تعاملی می‌گیرد؛ اطلاعات واقعی را در دستور، سورس یا Git ننویسید. ساخت مالک هم باید در همان محیط تولید انجام شود، نه با Compose محلی.

## اجرای وب برای توسعه‌دهنده

این بخش برای تغییر کد با بازخوانی خودکار است؛ برای استفادهٔ معمول، اجرای Docker بالای صفحه کافی است. **Node24** لازم است و Backend باید طبق مراحل بالا آماده باشد.

وب Docker را متوقف کنید تا پورت۳۱۰۰ آزاد شود؛ API و DB روشن می‌مانند:

```powershell
docker compose --profile website stop web
npm ci
npm run dev -- --port 3100
```

سایت توسعه هم روی http://127.0.0.1:3100 باز می‌شود و به Backend محلی روی۸۰۰۰ متصل است. برای پایان توسعه `Ctrl+C` را بزنید و وب Docker را دوباره با `docker compose --profile website up -d --wait web` روشن کنید.

بررسی کد:

```powershell
npm run lint
npm run build
npm run typecheck
```
