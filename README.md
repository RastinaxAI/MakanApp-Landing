# ماکان — راهنمای اجرای سایت و پنل مدیریت

سایت معرفی ماکان و پنل مدیریت مستقل آن؛ شامل صفحه‌ساز تصویری، مرکز آموزش، رسانه‌ها و CRM مدارس و درخواست‌های دمو.

**مسیر کار:** اجرای برنامه‌ها ← بازکردن سایت ← ورود مدیر با شماره همراه ← مدیریت محتوا و درخواست‌ها.

## اجرای سریع همین نسخهٔ آماده

فایل‌های کمکی راه‌اندازی حذف شده‌اند؛ اجرا با دستورهای همین سند انجام می‌شود. برای رفتن به پوشه پروژه در PowerShell:

```powershell
Set-Location 'C:\Users\OmidrezaBagheriyan\Desktop\MakanWebsite'
```

اگر پروژه قبلاً راه‌اندازی شده است، سرویس‌های موجود را روشن کنید. برای نصب تازه، مراحل بخش «نصب اولیه روی سیستم جدید» را انجام دهید.

۱. **Docker Desktop** را باز کنید و صبر کنید تا آماده شود.

۲. **PowerShell 7** را باز کنید و این دستورها را اجرا کنید:

```powershell
# دستور را از ریشهٔ پروژه اجرا کنید
docker compose --profile website up -d --wait db api web maintenance
```

۳. این آدرس‌ها را باز کنید:

| بخش | آدرس |
| --- | --- |
| سایت | http://127.0.0.1:3100 |
| ورود پنل مدیریت | http://127.0.0.1:3100/admin/login |
| بررسی سلامت برنامه‌ها | http://127.0.0.1:3100/health/ready |

۴. در صفحهٔ ورود، شمارهٔ مدیر ثبت‌شده را وارد کنید، **«دریافت کد ورود»** را بزنید و در حالت توسعه، کد **111111** را وارد کنید.

ورود پنل با شمارهٔ همراه مدیر و کد یک‌بارمصرف انجام می‌شود. در حالت توسعه پیامکی ارسال نمی‌شود؛ فقط شمارهٔ متصل به حساب مدیر فعال اجازهٔ ورود دارد. در محیط عملیاتی، ارسال واقعی کد به تنظیمات معتبر ملی‌پیامک نیاز دارد.

## اعمال تغییرات سایت

برای ساخت و اجرای نسخه تازه فرانت‌اند، بدون ایجاد مجدد دیتابیس:

```powershell
docker compose --profile website build web
docker compose --profile website up -d --no-deps --force-recreate --wait web
```

سپس صفحه را با Ctrl+F5 تازه کنید. وضعیت و لاگ‌ها:

```powershell
docker compose --profile website ps
docker compose --profile website logs -f --tail 100 web api
```

Ctrl+C مشاهده لاگ را می‌بندد و سرویس‌ها را متوقف نمی‌کند.

## بعد از ورود چه کار کنیم؟

از منوی **«راهنمای تصویری پنل»** در [مرکز راهنما](http://127.0.0.1:3100/admin/help) شروع کنید. بالای هر صفحه، **«راهنمای این صفحه»** تصویر ابزار و مراحل کوتاه همان کار را نشان می‌دهد. داخل صفحه‌ساز، دکمهٔ راهنما در ابزارهای کناری آن است.

در بخش عمومی سایت، زیر منوی اصلی **«شما اینجا هستید»** موقعیت شما را نشان می‌دهد. **«راهنمای صفحه»** را بزنید تا تصویر واقعی صفحه، مراحل کار و مسیر بعدی باز شود. این راهنما در صفحهٔ اصلی، امکانات، راهکارها، آموزش، وبلاگ، پرسش‌ها، درخواست دمو و تماس در دسترس است. برای خواندن جزئیات تصویر، **بزرگنمایی** و سپس **اندازهٔ اصلی** را بزنید.

در [آموزش ماکان](http://127.0.0.1:3100/learn)، از **«از کجا شروع کنم؟»** نقش خود را انتخاب کنید. داخل آموزش، فهرست بخش‌ها و دکمه‌های قبلی/بعدی کمک می‌کنند مسیر مطالعه را دنبال کنید. فقط محتوای منتشرشده نمایش داده می‌شود؛ اگر فهرست خالی است، مدیر باید آموزش واقعی را در پنل ایجاد و منتشر کند. روش درج تصویر و انتشار در [راهنمای نویسنده](docs/help-authoring.md) آمده است.

### فهرست محتوای سایت

در **محتوای سایت**، وضعیت را از دکمه‌های بالای فهرست انتخاب کنید. برای پیدا کردن محتوا، عنوان یا نوع آن را مشخص کنید و **اعمال فیلتر** را بزنید. **افزودن محتوا** پنل ساخت پیش‌نویس را باز می‌کند.

در هر ردیف، **ویرایش** برگه را باز می‌کند و آیکون چشم برای پیش‌نمایش خصوصی است. منوی سه‌نقطه، تاریخچه و بایگانی را نشان می‌دهد. بایگانی تأیید می‌خواهد؛ محتوا را از نمایش عمومی خارج می‌کند و سابقهٔ نسخه‌ها را نگه می‌دارد.

### کتابخانه و طراحی سراسری سایت

در **قالب‌ها و طراحی سایت**، طرح‌های ذخیره‌شده را ببینید و با دسته‌بندی، جست‌وجو و وضعیت پیدا کنید. **ساخت طرح جدید** پنلی برای انتخاب نوع و نام طرح باز می‌کند؛ پس از ساخت، وارد بوم درگ‌ودراپ می‌شوید. برای ویرایش صفحات فعلی، **ویرایش برگه‌های سایت** را بزنید.

در تب **طراحی سراسری**، رنگ و فونت یا سربرگ و پابرگ مشترک را تغییر دهید و **ذخیره طراحی سراسری** را بزنید. فقط سربرگ و پابرگ منتشرشده قابل اتصال هستند. این تب برای مدیر دارای دسترسی تنظیمات نمایش داده می‌شود.

### ویرایش صفحه و گذاشتن عکس داخل تب

1. در **محتوای سایت**، برگه را انتخاب کنید؛ مستقیم وارد **بوم تمام‌صفحه** می‌شوید. فرم‌های مشخصات و انتشار در پنل کناری هستند.
2. از نوار ابزار کناری، **عناصر** را باز کنید، عنصر را جست‌وجو کنید و آن را داخل صفحه یا کانتینر بکشید. با کلیک روی عنصر در صفحه، تنظیمات همان عنصر کنار بوم باز می‌شود. برای تغییر ترتیب، عنصر را روی بوم یا در **لایه‌ها** بکشید.
3. در **محتوا**، متن و تصویر را تغییر دهید. برای تب‌ها، روی خود تب در صفحه یا نام آن در «فهرست تب‌ها» کلیک کنید؛ **عنوان تب، تیتر داخل تب و متن تب** متعلق به همان تب هستند.
4. دکمهٔ **تصویر داخل تب** را بزنید و در **تصویر داخل این تب**، «انتخاب یا بارگذاری تصویر» را بزنید. عکس موجود را از کتابخانه انتخاب کنید یا فایل و متن جایگزین را وارد کنید و «بارگذاری و انتخاب» را بزنید. عکس بلافاصله در همان تب دیده می‌شود.
برای متن قالب‌بندی‌شده یا عکس میان پاراگراف‌ها، در «متن و پیوند» گزینهٔ **متن غنی و تصاویر داخل متن** را باز کنید.

5. در **استایل** رنگ و فونت را تنظیم کنید؛ در **پیشرفته** فاصله، اندازه و چیدمان را تغییر دهید. دکمه‌های **نمای دسکتاپ، تبلت و موبایل** بالای بوم هستند؛ پیش‌نمایش با عرض واقعی همان دستگاه و بزرگ‌نمایی متناسب با فضای موجود نمایش داده می‌شود.
6. **ذخیره صفحه‌ساز** را بزنید یا از `Ctrl+S` استفاده کنید؛ با آیکون چشم «پیش‌نمایش ذخیره‌شده» را بررسی کنید و سپس **انتشار** را بزنید. ذخیرهٔ پیش‌نویس به‌تنهایی سایت عمومی را تغییر نمی‌دهد.

**تنظیمات برگه** در نوار کناری شامل عنوان، SEO، رنگ و فونت، زمان‌بندی و پیوند نسخه‌های قبلی است. **بخش‌های آماده** ابزار قالب، کپی و جای‌گذاری را در همان پنل نشان می‌دهد. پنل را می‌توان جمع کرد تا بوم بزرگ‌تر شود. در گوشی، پنل زیر بوم قرار می‌گیرد تا هر دو در دسترس باشند. فرم‌های دمو و تماس هنگام طراحی، ظاهر واقعی فرم را نشان می‌دهند؛ ورود اطلاعات و ارسال درخواست در این پیش‌نمایش غیرفعال است.

تب‌های مخاطبان صفحهٔ اصلی نیز از داخل همان بخش قابل ویرایش‌اند و برای هر تب تصویر مستقل دارند. عناصر «فهرست امکانات»، «مقالات» و بخش‌های متصل به محتوای مرجع، راهنمای **ویرایش محتوای مرجع** دارند؛ از همان‌جا برگهٔ مربوط را باز کنید. تغییر محتوای مرجع پس از انتشار آن در سایت دیده می‌شود.

برای جابه‌جایی، تکثیر یا حذف تب، از دکمه‌های پایین تنظیمات همان تب استفاده کنید. «نسخه‌های قبلی» امکان بازیابی به پیش‌نویس را حفظ می‌کند.

| کار | مسیر در پنل |
| --- | --- |
| تغییر ظاهر یا متن یک صفحه | محتوای سایت ← انتخاب برگه ← صفحه‌ساز |
| ساخت صفحهٔ جدید | محتوای سایت ← افزودن؛ سپس عنوان، Container و عناصر موردنیاز را اضافه کنید |
| تغییر نمایش موبایل | داخل صفحه‌ساز حالت موبایل را انتخاب کنید و تنظیمات همان اندازه را تغییر دهید |
| ذخیره و انتشار | ابتدا «ذخیره»، سپس «پیش‌نمایش» و «انتشار»؛ ذخیرهٔ پیش‌نویس به‌تنهایی سایت عمومی را عوض نمی‌کند |
| بازیابی نسخهٔ قبلی | تاریخچهٔ نسخه‌ها ← بازیابی به پیش‌نویس؛ پس از بررسی، منتشر کنید |
| مدیریت درخواست دمو | فروش و پروندهٔ مدارس ← سرنخ‌ها؛ درخواست‌های فرم سایت خودکار در این بخش ثبت می‌شوند |
| پیگیری یک مدرسه | بازکردن سرنخ ← نمای مشتری؛ اطلاعات مدرسه، افراد، یادداشت، فعالیت و دمو را تکمیل کنید |
| پیگیری فروش | فروش و پروندهٔ مدارس ← فرصت‌ها؛ کارت را به مرحلهٔ بعد بکشید یا مرحله را از فرم تغییر دهید |
| برنامه‌ریزی دمو | نمای مشتری ← دمو؛ کارشناس، زمان، نتیجه و اقدام بعدی را ثبت کنید |
| یادآوری‌ها | فروش و پروندهٔ مدارس ← اعلان‌ها؛ سرویس `maintenance` یادآوری‌های داخلی را پردازش می‌کند |

اعلان‌های CRM داخل پنل هستند. پیامک ورود فقط با اتصال ملی‌پیامک ارسال می‌شود؛ ارسال پیامک فروش و دمو فعلاً فعال نشده است. تصاویر شماتیک سایت اسکرین‌شات محصول نیستند؛ تصویر واقعی تأییدشده را از کتابخانهٔ رسانه انتخاب کنید. امکانات AI با وضعیت «در نقشهٔ راه» معرفی می‌شوند.

## نصب اولیه روی سیستم جدید

این بخش برای نصب تازه است. اگر نسخهٔ فعلی را اجرا می‌کنید، از بخش بالا استفاده کنید.

**پیش‌نیاز:** Docker Desktop در حالت Linux containers و PowerShell 7. برای اجرای Docker، نصب جداگانهٔ Node، Python و PostgreSQL لازم نیست. ساخت اولیه به اینترنت نیاز دارد و ممکن است چند دقیقه طول بکشد.

PowerShell را در پوشهٔ پروژه باز کنید. دستورها را به‌ترتیب اجرا کنید؛ اگر یک دستور خطا داد، پیش از دستور بعدی آن خطا را رفع کنید.

### ۱. ساخت تنظیمات خصوصی

```powershell
$panelRoot = (Get-Location).Path
foreach ($panelEnvName in @('.env', '.env.test')) {
    $panelEnvPath = Join-Path $panelRoot $panelEnvName
    $panelExisting = if (Test-Path -LiteralPath $panelEnvPath) { [IO.File]::ReadAllText($panelEnvPath) } else { '' }
    $panelLines = @()
    foreach ($panelKey in @('POSTGRES_PASSWORD', 'MIGRATION_DB_PASSWORD', 'API_DB_PASSWORD', 'AUTH_SECRET', 'AUTH_MFA_KEY')) {
        if ($panelExisting -notmatch "(?m)^$panelKey=") {
            $panelSecret = [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)).ToLowerInvariant()
            $panelLines += "$panelKey=$panelSecret"
        }
    }
    if ($panelLines.Count -gt 0) {
        $panelText = $panelExisting.TrimEnd() + [Environment]::NewLine + ($panelLines -join [Environment]::NewLine) + [Environment]::NewLine
        [IO.File]::WriteAllText($panelEnvPath, $panelText, [Text.UTF8Encoding]::new($false))
    }
}
```

این دستورها فایل‌های خصوصی `.env` و `.env.test` و کلیدهای لازم را آماده می‌کند؛ مقدارهای موجود را حفظ می‌کند. این فایل‌ها را داخل Git یا پیام عمومی قرار ندهید.

### ۲. ساخت برنامه‌ها

```powershell
docker compose --profile tools --profile website build api migrate maintenance
docker compose --profile website build web
```

ابتدا Backend و سرویس‌های هم‌تصویر آن ساخته می‌شوند، سپس وب؛ مصرف حافظه کمتر می‌شود.

### ۳. آماده‌کردن دیتابیس و اجرای Backend

```powershell
docker compose up -d --wait db
docker compose --profile tools run --rm migrate
docker compose up -d --wait api
```

`migrate` ساختار دیتابیس را با Alembic آماده یا به‌روز می‌کند. آن را قبل از اجرای نسخهٔ جدید برنامه انجام دهید.

### ۴. واردکردن محتوای اولیهٔ سایت

```powershell
docker compose exec -T api python -m app.commands.import_content
docker compose exec -T api python -m app.commands.refresh_learning_intro
docker compose exec -T api python -m app.commands.refresh_form_copy
docker compose exec -T api python -m app.commands.crm_backfill
docker compose exec -T db psql -U postgres -d makan_landing -c ANALYZE
```

این دستورها متن‌های اولیه را آماده می‌کنند و ویرایش‌های قبلی مدیر را حفظ می‌کنند. مقاله، ویدیو و درخواست مشتری فرضی اضافه نمی‌شود؛ آموزش‌ها را خودتان از پنل ایجاد و منتشر کنید.

### ۵. اجرای سایت و ساخت اولین مالک

```powershell
docker compose --profile website up -d --wait web maintenance
docker compose exec -it api python -m app.commands.admin bootstrap
```

در پاسخ به `Administrator phone`، شمارهٔ همراه مدیر اصلی را وارد کنید. سپس [صفحهٔ ورود پنل](http://127.0.0.1:3100/admin/login) را باز کنید و با همان شماره و کد توسعهٔ **111111** وارد شوید.

`bootstrap` فقط برای نصب تازه و فهرست خالی مدیران است. اگر پیام `An owner already exists` دیدید، حساب موجود را استفاده کنید؛ ساخت مالک را تکرار نکنید. مدیران بعدی را از **پیشخوان ← حساب‌های مدیران** اضافه کنید.

اگر حساب قدیمی با ایمیل دارید ولی شماره به آن متصل نیست:

```powershell
$managerEmail = Read-Host 'ایمیل حساب قدیمی'
docker compose exec -it api python -m app.commands.admin bind-phone --email $managerEmail
```

شمارهٔ همراه را در مرحلهٔ بعد وارد کنید. همان حساب حفظ می‌شود و نشست‌های قبلی آن بسته می‌شوند.

## اتصال ملی‌پیامک و فعال‌کردن ارسال واقعی

در منوی پنل، **مدیریت ← پنل پیامکی** را باز کنید:

1. نام کاربری ملی‌پیامک، **رمز وب‌سرویس** و **شناسهٔ الگوی خدماتی تأییدشده (Body ID)** را وارد کنید. الگو باید یک پارامتر برای کد ورود شش‌رقمی داشته باشد.
2. «اتصال پنل پیامکی فعال باشد» را انتخاب کنید. فعلاً حالت توسعه را روشن نگه دارید.
3. «دریافت کد تأیید تغییرات» را بزنید، کد توسعهٔ **111111** را وارد و تنظیمات را ذخیره کنید.
4. «بررسی اتصال» را بزنید. این بررسی پیامکی ارسال نمی‌کند؛ ارتباط و مشخصات ورود پنل را بررسی می‌کند.
5. برای فعال‌کردن ارسال واقعی، یک کد تأیید **جدید** دریافت کنید، حالت توسعه را خاموش و تنظیمات را ذخیره کنید. بین درخواست دوبارهٔ کد حداقل **۶۰ ثانیه** فاصله لازم است.
6. خارج شوید و دوباره وارد شوید؛ این بار باید کد تصادفی شش‌رقمی را از پیامک دریافت کنید.

اطلاعات پنل رمزگذاری می‌شوند و دوباره نمایش داده نمی‌شوند. کد تأیید هر تغییر فقط یک بار قابل استفاده است. خطای سرویس پیامکی باعث فعال‌شدن خودکار کد ثابت نمی‌شود. ارسال واقعی با حساب شما پس از ثبت مشخصات و الگوی معتبر قابل آزمایش است.

اگر تنظیم اشتباه پیامک، ورود **محلی** را قطع کرد، حالت توسعه را برگردانید:

```powershell
docker compose exec -it api python -m app.commands.sms reset-debug
```

این دستور در محیط Production و staging مجاز نیست و کد پیامکی ثابت در محیط انتشار فعال نمی‌شود.

```powershell
docker compose --profile website stop web api maintenance db
```

داده‌ها و تصاویر پس از توقف باقی می‌مانند. از `down --volumes` برای این محیط استفاده نکنید؛ داده‌های ذخیره‌شده را حذف می‌کند.

**به‌روزرسانی همین کامپیوتر به V2:** ابزار زیر ابتدا برنامه‌ها را می‌سازد، از دیتابیس و رسانه‌ها پشتیبان رمزگذاری‌شده می‌گیرد، آن را روی دیتابیس جداگانه بازیابی و مقایسه می‌کند، سپس Migration و انتقال محتوا را اجرا می‌کند. اطلاعات قبلی و نسخه‌های قدیمی حفظ می‌شوند. برای این ابزار، محیط Python پروژه و دیتابیس تست باید آماده باشند:

```powershell
docker compose --env-file .env.test -f compose.test.yaml up -d --wait
.\apps\api\.venv\Scripts\python.exe -X utf8 .\scripts\upgrade-development.py
```

ساخت مالک و ورود دوبارهٔ محتوای اولیه لازم نیست. پشتیبان و کلید خصوصی آن در `.backups` قرار می‌گیرند؛ هر دو را در محل امن نگه دارید. این ابزار برای محیط محلی همین پروژه است؛ راهنمای سرور در بخش انتشار قرار دارد. توقف برنامه، داده‌ها را حذف نمی‌کند.

## اگر سایت باز نشد

```powershell
# وضعیت برنامه‌ها؛ سرویس‌ها باید running و healthy باشند
docker compose --profile website ps

# خطاهای اخیر
docker compose --profile website logs --tail 60 web api
```

| مشکل | کار لازم |
| --- | --- |
| Docker در دسترس نیست | Docker Desktop را باز کنید و تا آماده‌شدن آن صبر کنید. |
| خطای تنظیمات یا متغیر محیطی | دستورهای «ساخت تنظیمات خصوصی» را اجرا کنید؛ فایل `.env` موجود را حفظ کنید. |
| پورت۳۱۰۰ اشغال است | اجرای دیگر همین سایت روی۳۱۰۰ را متوقف کنید و دوباره تلاش کنید. |
| Backend آماده نیست یا سلامت۵۰۳ است | وضعیت DB/API و خروجی `migrate` را بررسی کنید؛ لاگ‌ها را بخوانید. |
| شماره اجازهٔ ورود ندارد | شماره باید برای حساب مدیر فعال ثبت شده باشد؛ بخش ساخت یا اتصال مدیر را ببینید. |
| کد نادرست یا منقضی است | کد جدید دریافت کنید؛ فاصلهٔ ارسال و شمارش صفحه را رعایت کنید. |
| پیامک نمی‌رسد | تنظیمات پنل، رمز وب‌سرویس و الگوی تأییدشده را بررسی کنید؛ برای بازیابی محلی از `reset-debug` استفاده کنید. |
| صفحهٔ اصلی محتوای اولیه ندارد | بخش «واردکردن محتوای اولیهٔ سایت» را بررسی کنید. |

فایل `.env` را برای رفع خطا حذف نکنید؛ ساخت رمز تازه، رمز ذخیره‌شدهٔ دیتابیس موجود را عوض نمی‌کند.

## انتشار روی دامنهٔ واقعی

### انتقال پروژه

سورس برنامه در `apps/`، تنظیمات زیرساخت در `infrastructure/` و ابزارهای اجرا و نگهداری در `scripts/` قرار دارند. فایل‌های Compose، Dockerfile، فایل‌های قفل وابستگی و دو قالب تنظیمات محیط را همراه سورس نگه دارید.

برای ساخت بستهٔ انتقال، در صورت نیاز از ریشهٔ پروژه اجرا کنید؛ کتابخانهٔ اضافی لازم نیست:

```bash
python scripts/package-release.py
```

ZIP و فایل SHA256 در `release/` ساخته می‌شوند. این پوشه خروجی تولیدشده است و وارد Git یا Build نمی‌شود. ابزار بسته‌بندی، فایل‌های خصوصی، کش‌ها، بکاپ‌ها و اطلاعات دیتابیس را وارد ZIP نمی‌کند.

**اطلاعات فعلی جدا از سورس هستند.** مطالب منتشرشده، مدیران و درخواست‌ها داخل دیتابیس‌اند و تصاویر بارگذاری‌شده در Volume رسانه نگهداری می‌شوند. برای انتقال همین اطلاعات به سرور از [راهنمای پشتیبان‌گیری و بازیابی](docs/backup-restore-runbook.md) استفاده کنید؛ نصب تازه جای انتقال داده را نمی‌گیرد. `.env` و `.backups` خصوصی‌اند و نباید همراه سورس عمومی آپلود شوند.

### نصب تازه روی سرور

Docker Engine، Compose v2، Python 3.13 و `uv` باید نصب باشند؛ دامنه به IP سرور اشاره کند و پورت‌های ۸۰ و ۴۴۳ باز باشند. از داخل `/opt/makan-landing`:

```bash
uv sync --locked --project apps/api
apps/api/.venv/bin/python scripts/production.py --env-file /etc/makan-landing/production.env init --domain YOUR_DOMAIN
apps/api/.venv/bin/python scripts/production.py --env-file /etc/makan-landing/production.env build
```

`YOUR_DOMAIN` را با دامنهٔ خودتان عوض کنید. دستور `init` تنظیمات و کلیدهای مستقل می‌سازد و فایل موجود را بازنویسی نمی‌کند. در فایل `/etc/makan-landing/production.env`، پس از تأیید محتوای تماس و سیاست‌های انتشار، `PUBLIC_POLICY_APPROVED=true` را تنظیم کنید؛ سپس **فقط برای نصب تازه**:

```bash
apps/api/.venv/bin/python scripts/production.py --env-file /etc/makan-landing/production.env deploy --import-approved-marketing
docker compose -f compose.production.yaml --env-file /etc/makan-landing/production.env exec -it api python -m app.commands.admin bootstrap
docker compose -f compose.production.yaml --env-file /etc/makan-landing/production.env exec -it api python -m app.commands.sms configure
apps/api/.venv/bin/python scripts/production.py --env-file /etc/makan-landing/production.env status
```

در `bootstrap` شمارهٔ مالک و در `sms configure` مشخصات واقعی ملی‌پیامک را وارد کنید. سپس سایت را روی `https://YOUR_DOMAIN` و پنل را روی `https://YOUR_DOMAIN/admin/login` باز کنید. تنظیمات پیامکی و کلیدهای موجود را هنگام انتقال دیتابیس حفظ کنید؛ `init` و ساخت مالک تازه، برای جایگزین‌کردن اطلاعات محیط موجود نیستند.

بستهٔ سرور به وابستگی‌های نصب‌شدهٔ محلی نیاز ندارد. برای توسعهٔ مجدد، وابستگی‌های وب با `npm ci` و وابستگی‌های API با `uv sync --locked --project apps/api` نصب می‌شوند.

جزئیات تنظیم سرور و HTTPS در [راهنمای استقرار](docs/production-runbook.md) و روش حفاظت از داده‌ها در [راهنمای پشتیبان‌گیری و بازیابی](docs/backup-restore-runbook.md) آمده است. برای نصب عملیاتی، دامنه و تنظیمات همان سرور را وارد کنید.

پیش از انتشار عمومی، [یافته‌های امنیتی و موارد باقی‌مانده](docs/security-findings.md) را بررسی کنید؛ اسکن imageها چند هشدار High بسته‌های پایه ثبت کرده است.

در محیط انتشار، کد ثابت **111111** غیرفعال است. قبل از اولین ورود مدیر، اپراتور با فایل تنظیمات همان محیط، اتصال پیامکی را آماده می‌کند؛ نمونهٔ مسیر مطابق راهنمای استقرار:

```bash
docker compose -f compose.production.yaml --env-file /etc/makan-landing/production.env exec -it api python -m app.commands.sms configure
```

این دستور مشخصات ملی‌پیامک را به‌صورت تعاملی می‌گیرد؛ اطلاعات واقعی را در دستور، سورس یا Git ننویسید. ساخت مالک هم باید در همان محیط تولید انجام شود، نه با Compose محلی.

## اجرای وب برای توسعه‌دهنده

این بخش برای تغییر کد با بازخوانی خودکار است؛ برای استفادهٔ معمول، اجرای Docker بالای صفحه کافی است. **Node24** لازم است و Backend باید طبق مراحل بالا آماده باشد.

وب Docker را متوقف کنید تا پورت۳۱۰۰ آزاد شود؛ API و DB روشن می‌مانند:

```powershell
docker compose --profile website stop web
npm ci
npm run dev -- --port 3100
```

سایت توسعه هم روی http://127.0.0.1:3100 باز می‌شود و به Backend محلی روی۸۰۰۰ متصل است. برای پایان توسعه `Ctrl+C` را بزنید و وب Docker را دوباره با `docker compose --profile website up -d --wait web` روشن کنید.

برای اجرای production محلی پس از توقف وب Docker و با روشن‌بودن API و دیتابیس:

```powershell
npm ci
npm run build
npm start -- --port 3100
```

فرمان start مستقیماً Next.js را اجرا می‌کند و فایل راه‌انداز جداگانه ندارد. ساخت Docker همچنان خروجی standalone مستقل دارد.

بررسی کد:

```powershell
npm run lint
npm run build
npm run typecheck
```

## بررسی سرعت و اتصال محتوای سایت

دریافت تنظیمات عمومی به‌صورت هم‌زمان انجام می‌شود و هر صفحه فقط فهرست‌های موردنیاز ویجت‌های خودش را می‌گیرد. درخواست‌های عمومی یکسان فقط تا پایان پاسخ با یکدیگر مشترک می‌شوند؛ نتیجه یا خطا برای بازدید بعدی نگهداری نمی‌شود، بنابراین انتشار یا حذف محتوا نیاز به پاک‌کردن کش ندارد.

برای Timeout یا قطع موقت اتصال، درخواست GET یک بار دیگر، در سقف مجموع ۸ ثانیه، تلاش می‌شود. ثبت فرم‌ها تکرار خودکار ندارد. قطع کامل API همچنان پیام خطای واقعی نمایش می‌دهد؛ در این حالت ابتدا سلامت سرویس‌ها و منابع میزبان را بررسی کنید:

```powershell
docker compose --profile website ps
docker compose --profile website logs --since 10m web api
```

آزمون منطق دریافت محتوا، اشتراک درخواست‌ها و وابستگی ویجت‌ها، پس از `npm ci` و با Node24:

```powershell
node --test apps/web/tests/unit/*.test.mjs
```

اندازه‌گیری محلی روی Docker در ۲۷ اکتبر ۲۰۲۶، پس از گرم‌شدن سرویس، برای هر صفحه شامل ۱۰ درخواست متوالی و ۱۶ درخواست با هم‌زمانی ۴ بود. میانهٔ زمان دریافت کامل HTML صفحهٔ امکانات از ۳۲۲ به ۱۴۱ میلی‌ثانیه و در حالت هم‌زمان از ۱۰۸۹ به ۱۴۳ میلی‌ثانیه رسید؛ میانهٔ صفحهٔ اصلی در حالت هم‌زمان از ۱۰۰۳ به ۳۷۴ میلی‌ثانیه رسید. در ۵۲ درخواست اندازه‌گیری‌شدهٔ نسخهٔ جدید خطایی دیده نشد. این نتایج آزمایش محلی‌اند و تضمین سرعت اینترنت یا Core Web Vitals کاربران نیستند.

هنگام Build روی میزبان ۸ گیگابایتی، RAM آزاد به کمتر از ۷۰۰ مگابایت رسید. در اولین درخواست پس از Build و بررسی اولیهٔ FAQ در مرورگر، Timeout ثبت شد. تکرار کامل بررسی مرورگر روی ۹ مسیر، نمایش در عرض‌های ۳۹۰، ۷۶۸ و ۱۴۴۰، پاسخ ۴۰۴ و حفاظت پنل موفق بود. تلاش مجدد جای منابع کافی سرور را نمی‌گیرد و حذف کامل خطای مقطعی در شرایط فشار منابع تأیید نشده است. ساخت image را پیش از جایگزینی سرویس و ترجیحاً خارج از میزبان سرویس‌دهی انجام دهید.

Lighthouse موبایل روی همین محیط محلی: امتیاز Performance امکانات ۹۱، دسترس‌پذیری و Best Practices هر دو ۱۰۰ و CLS برابر صفر بود. برای صفحهٔ اصلی سه اجرا امتیازهای ۶۷، ۸۷ و ۸۸ دادند؛ میانهٔ ۸۷ هنوز به هدف ۹۰ نرسیده و میانهٔ LCP حدود ۳٫۴۲ ثانیه بود. امتیاز SEO برابر ۶۶ به‌علت `noindex` عمدی محیط فعلی است؛ تا اعلام دامنهٔ نهایی، ایندکس خودکار فعال نشده است. این امتیازها دادهٔ آزمایشگاهی‌اند، نه اندازه‌گیری کاربران واقعی.

Next.js و تنظیم ESLint آن به نسخهٔ اصلاحی 16.4.3 ارتقا یافته‌اند. اسکن وابستگی‌ها همچنان سه هشدار High در زنجیرهٔ `@puckeditor/core → @tiptap/html → happy-dom` دارد؛ این سه هشدار به یک مشکل وابستگی مربوط‌اند. [اصلاح رسمی happy-dom](https://github.com/capricorn86/happy-dom/security/advisories/GHSA-834v-8h66-3h79) در نسخهٔ 21.0.4 است و با محدودهٔ نسخهٔ فعلی صفحه‌ساز تطابق ندارد. رفع کامل آن به ارتقای سازگار و آزمون صفحه‌ساز نیاز دارد؛ پروژه نباید از این نظر کاملاً بدون هشدار تلقی شود.
